# assets — ภาพตัวอย่างผลิตภัณฑ์

ภาพที่ `AppShowcaseDialog` วาด **ชุดเดียวของทั้งแพลตฟอร์ม** ไม่ใช่ไฟล์ที่แต่ละแอปคัดลอกไปเก็บเอง

## ทำไมอยู่ที่นี่ ไม่ใช่ใน `public/` ของแต่ละแอป

เดิมทุกแอปเก็บสำเนาไว้ที่ `public/images/app-showcase/` ของตัวเอง แล้วมันก็ดริฟต์จริง —
วัดเมื่อ 2026-08-25: hr-web ได้ภาพชุดใหม่ไปแล้ว ส่วน Portal ยังเป็นชุดวันที่ 17 ส.ค.
⇒ กล่องเดียวกันแสดงคนละภาพขึ้นกับว่าผู้ใช้ยืนอยู่แอปไหน และการอัปเดตแปลว่าต้อง `cp`
ข้ามรีโปด้วยมือทุกครั้ง

## ทำไมเป็นไฟล์ ไม่ใช่ data URL แบบ `brand/app-marks.ts`

ขนาด: ภาพทั้งชุด **224 KB** → เป็น base64 กลายเป็น **307 KB** ซึ่งจะทำให้ `dist/index.js`
โตจาก 404 KB เป็น **711 KB (+76%)** กับ *ทุกแอปที่ import DS* แม้ไม่เคยเปิดกล่องนี้เลย
ต่างจากเครื่องหมายแอปที่ตัวละ 1–5 KB และถูกวาดในทุกหน้าอยู่แล้ว

เป็นไฟล์แล้วยังได้: เบราว์เซอร์ cache แยกจาก JS · โหลดเฉพาะใบที่เปิดจริง · ไม่ต้อง decode base64

## วิธีใช้

แอป **import ที่อยู่ของไฟล์** แล้วส่งเข้า `showcaseAssets` / `assets`:

```tsx
import medipayPreview from "@mediact/react/assets/medipay-preview.webp";

<AppLauncher showcaseAssets={{ medipay: { composed: medipayPreview.src } }} />
```

Next.js จะ hash ไฟล์และเสิร์ฟเองผ่าน asset pipeline ⇒ ไม่มีสำเนาใน `public/` ของแอปอีก
และถ้าไฟล์หายไปจาก DS จะเป็น **compile error** ไม่ใช่ภาพแตกเงียบ ๆ บนจอ

> `.src` ต้องมี เพราะ Next คืน object `{ src, width, height }` ไม่ใช่ string
> (bundler อื่นคืน string ตรง ๆ — เขียนให้รองรับทั้งสองแบบถ้าจำเป็น)

## ทำไม dialog ไม่ import เองเลย

ลองแล้วไม่ได้: DS ถูก prebuild ด้วย tsup ⇒ `import x from "./assets/x.webp"` ในซอร์สจะถูก
esbuild แปลงเป็น path ที่ relative กับ `dist/` ซึ่งไม่มีใครเสิร์ฟตอน runtime (ไฟล์อยู่ใน
`node_modules` ไม่ได้ผ่าน asset pipeline ของแอป) ⇒ ต้องให้ **แอป** เป็นคน import
เพื่อให้ bundler ของแอปจัดการ

## ชนิดของภาพ

| ไฟล์ | ใช้กับ |
|---|---|
| `<key>-preview.webp` | ภาพเดียวที่ **ซ้อนจอกับการ์ดมาแล้ว** — ส่งเป็น `composed` |
| `medihr-preview-wide.webp` + `-card.webp` | ชุดเก่าที่ยังแยกสองใบ — ส่งเป็น `wide`/`card` |

MediHR ยังไม่มีภาพชุดใหม่จากดีไซน์ จึงยังเป็นแบบสองใบอยู่

⚠️ ภาพพวกนี้เป็น **screenshot ของจอจริง** ⇒ ต้องถ่ายใหม่เมื่อ UI ของผลิตภัณฑ์นั้นเปลี่ยน
การย้ายมาไว้ที่นี่แก้เรื่อง *สำเนาไม่ตรงกัน* ไม่ได้แก้เรื่อง *ภาพล้าสมัย*
