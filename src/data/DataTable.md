### แถบแบ่งหน้า

วัดจาก Portal: **ตัวเลือกจำนวนแถวสูง 32px** ไม่มีบรรทัดว่างใต้ช่อง

| | ก่อน | หลัง |
|---|---|---|
| ความสูงแถบ | **73px** | **53px** |
| ช่องเลือกจำนวนแถว | 56px (36 + บรรทัดที่จองเปล่า) | 36px |
| ป้าย "Rows per page" | ตกบรรทัดเป็น 2 แถวที่ ≤1000px | บรรทัดเดียว |
| ที่จอ 375px | **ล้น 390 บนพื้นที่ 341** | ตัดบรรทัดเป็นชั้น ไม่ล้น |

🔴 รากคือ `Select` ใช้ `FloatingFieldShell` ที่ออกแบบมาสำหรับ**ฟอร์ม** — จองบรรทัด error
ไว้เสมอกันเลย์เอาต์กระโดด ซึ่งถูกสำหรับฟอร์ม แต่ในแถบเครื่องมือไม่มี error มาแสดงอยู่แล้ว
บรรทัดนั้นจึงเป็นที่ว่างเปล่าที่ดันทั้งแถบสูงขึ้น 20px

⇒ `Select` เปิด prop `reserveMessageSpace` ให้ปิดได้ (เดิมมีแต่ที่ shell ไม่มี field ตัวไหนส่งต่อ)

⚠️ **`flex-wrap` ที่กล่องนอกอย่างเดียวไม่พอ** — กลุ่มขวาเป็นชิ้นเดียวในสายตาของมัน
ต้องให้กลุ่มขวาตัดบรรทัดเองด้วย ไม่งั้นที่จอแคบจะล้นออกนอกการ์ด

วัดครบ 6 ความกว้าง (1440 · 1024 · 768 · 640 · 480 · 375) — **ไม่ล้นทุกตัว**

#### 🔄 ปรับใหม่ 2026-08-09 — ยกทรงจาก Portal ทั้งแถบ

```
จำนวนแถวต่อหน้า:  10 ⌄     1-10 จาก 13     ‹  ›
```

ของเดิมเป็น "ซ้าย–ขวา" (ช่วงอยู่ซ้าย · ตัวเลือก+ปุ่มอยู่ขวา พร้อมตัวเลข `1 / 3` คั่น)
ของ Portal เป็น **กลุ่มเดียวชิดซ้าย** และปุ่มเป็น**ไอคอนล้วน**

| | เดิม | ใหม่ (= Portal) |
|---|---|---|
| การจัดวาง | ซ้าย ↔ ขวา | กลุ่มเดียวชิดซ้าย `gap-8` |
| ช่องเลือกจำนวนแถว | มีกรอบ กว้าง 80 | **ไม่มีกรอบ** สูง 32 กว้าง 56 |
| ปุ่มเปลี่ยนหน้า | `Prev` / `Next` มีข้อความ | ไอคอนล้วน **28×28** · จาง 0.3 เมื่อกดไม่ได้ |
| ตัวบอกหน้า | `1 / 3` | **ไม่มี** — ช่วง `1-10 จาก 13` บอกอยู่แล้ว |
| ตัวนับที่เลือก | ซ้ายสุด | ท้ายแถบ (`ml-auto`) |

🔴 **ตัวนับที่เลือกย้ายไปท้ายแถบ** เพราะมันปรากฏ ๆ หาย ๆ ตามการติ๊ก —
อยู่ซ้ายแล้วทุกอย่างในแถบจะเลื่อนทั้งแถวทุกครั้งที่ติ๊ก

🔴 **ช่องเลือกใช้ `border-transparent` ไม่ใช่ `border-0`** — `border-0` ลบ*ความหนา*
ทำให้ช่องแคบลง 2px แล้วตัวเลขขยับตอน hover (บทเรียนเดิมจาก skeleton ของปุ่ม)

🔴 **ปุ่มไอคอนล้วนต้องมีชื่อ** — ไม่มี `aria-label` = โปรแกรมอ่านหน้าจอประกาศว่า
"ปุ่ม" เฉย ๆ ทั้งสองอัน แยกไม่ออกว่าอันไหนไปหน้าไหน · ชื่อมาจาก `labels.prev/next`

## ข้อความ — ทุกตัวมาจากแอป ไม่มีคำไหนตายตัวใน DS

DS ไม่มี i18n อยู่ในตัว **และไม่ควรมี** — คำแปลเป็นของแอป
`labels` จึงครอบ**ทุกคำที่ DS พูดเอง** รวมถึงคำที่ตาไม่เห็น (`aria-label`)

```tsx
labels={{
  selectAllAriaLabel: "เลือกทุกแถว",
  selectRowAriaLabel: "เลือกแถวนี้",
  empty:  { title: "ยังไม่มีรายการ", description: "กดปุ่มเพิ่มเพื่อเริ่มต้น" },
  error:  { title: "เกิดข้อผิดพลาด", description: "โหลดข้อมูลไม่สำเร็จ" },
  retry: "ลองใหม่",
  prev: "หน้าก่อนหน้า",      // ← ชื่อปุ่มไอคอน ไม่ใช่ข้อความบนปุ่ม
  next: "หน้าถัดไป",
  rowsPerPage: "จำนวนแถวต่อหน้า:",
  toggleGroup: "พับ/กางกลุ่ม",
  selected: (n) => `เลือกแล้ว ${n} รายการ`,
  of: (s, e, t) => `${s}-${e} จาก ${t}`,
}}
```

| ที่อยู่ | ทำไม |
|---|---|
| `prev` `next` `toggleGroup` เป็น `string` ไม่ใช่ `ReactNode` | ปุ่มเป็นไอคอนล้วน ⇒ ข้อความไปเป็น `aria-label` ซึ่งรับได้แค่ string · ส่ง element มาจะได้ `[object Object]` |
| `selected` `of` เป็น**ฟังก์ชัน** | ลำดับคำต่างกันตามภาษา — ต่อสตริงเองใน DS = บังคับไวยากรณ์อังกฤษให้ทุกภาษา |
| ป้ายหัวกลุ่มไม่อยู่ใน `labels` | มันขึ้นกับ**ข้อมูล** ไม่ใช่คำคงที่ ⇒ อยู่ที่ `groupLabel` ซึ่งรับคีย์+จำนวนไปประกอบเอง |

🔴 **มีเทสจับคำอังกฤษที่หลุด** — render 4 สถานะ (ปกติ · ว่าง · ผิดพลาด · จัดกลุ่ม)
พร้อม `labels` ภาษาไทยครบ แล้วสแกนทั้งข้อความบนจอ**และ `aria-label` ทุกตัว**
ว่าไม่มีคำตั้งต้นของ DS เหลืออยู่ · พร้อมเทสกลับด้านที่ยืนยันว่าไม่ส่ง `labels`
แล้วต้องได้อังกฤษจริง (ไม่งั้นเทสแรกผ่านฟรีเมื่อข้อความหายไปทั้งหมด)

⚠️ **เพิ่มคำใหม่ในโค้ดต้องเพิ่มใน `DS_DEFAULT_COPY` ของเทสด้วย** ไม่งั้นด่านนี้มองไม่เห็น

## แช่คอลัมน์ (`freezeColumns`)

```tsx
<DataTable
  minTableWidth={1400}
  freezeColumns={{ left: 1, right: 1 }}   // ชื่อค้างซ้าย · ปุ่มค้างขวา
/>
```

นับเฉพาะคอลัมน์**ข้อมูล** — ช่องติ๊กเลือกแช่ตามให้เองเมื่อ `left ≥ 1`
(ปล่อยให้ช่องติ๊กเลื่อนหายไปขณะที่ชื่อยังอยู่ = ติ๊กแถวที่มองไม่เห็นว่าแถวไหน)

⚠️ **ไม่มีผลถ้าไม่มีอะไรให้เลื่อน** — ต้องตั้ง `minTableWidth` ก่อน ไม่งั้นดูเหมือน prop เสีย

### 🔴 บั๊กที่เจอตอนวัด: การวัดกินผลลัพธ์ของตัวเอง

รอบแรกคำนวณระยะจาก `offsetLeft` ของหัวคอลัมน์ ผลคือ **ฝั่งขวาไปติดขอบซ้าย**

| | ค่าที่ควรได้ | ค่าที่วัดได้ |
|---|---|---|
| `actions.offsetLeft` | 1263 | **0** |
| `right` ที่คำนวณออกมา | 0 | **634** |
| ตำแหน่งบนจอ | 628.7 | **−5.3** (หลุดออกนอกจอ) |

ราก: **พอใส่ `position: sticky` ให้เซลล์แล้ว `offsetLeft` ของมันเปลี่ยนตามการตรึง**
⇒ วัด → เขียนสไตล์ → วัดใหม่ได้ค่าที่เพี้ยน → ลู่เข้าค่าผิดแล้วนิ่ง

และ `634 = 1400 − 766` (ความกว้างตาราง − ความกว้างช่องมอง) ซึ่งเป็นเลขที่
"ดูมีเหตุผล" มากพอที่จะไม่มีใครสงสัยถ้าไม่ได้เอาไปเทียบกับตำแหน่งจริงบนจอ

**ทางแก้: บวกจาก `rect.width` อย่างเดียว ไม่อ่านตำแหน่งเลย**
— sticky ย้ายตำแหน่ง แต่ไม่เปลี่ยนขนาด ⇒ ความกว้างไม่ถูกกระทบ

```
ระยะซ้ายของคอลัมน์ i = Σ ความกว้างของคอลัมน์ 0..i-1
ระยะขวาของคอลัมน์ i = Σ ความกว้างของคอลัมน์ i+1..n-1
```

### ทำไมไม่ใช้ column pinning ของ TanStack

`column.getStart('left')` บวกจาก `columnDef.size` — แต่ DS ตีความ `size` เป็นความกว้าง
**ขั้นต่ำ** ⇒ วัดจริงคอลัมน์ที่ตั้ง 200 ได้ **211.2** และที่ตั้ง 160 ได้ **168.9**
สะสมข้ามหลายคอลัมน์แล้วคอลัมน์ที่สองจะแช่ทับตัวแรกโดยไม่มีอะไรฟ้อง

### รายละเอียดอื่นที่ต้องระวัง

- **เส้นคั่นเป็น `box-shadow` ไม่ใช่ `border`** — ตารางถูกตั้ง `border-collapse: collapse`
  และเส้นขอบของเซลล์ sticky ไม่ถูกวาดในโหมดนั้น (เส้นเป็นของตาราง ไม่ใช่ของเซลล์)
- **เงามีเฉพาะคอลัมน์ในสุดของแต่ละฝั่ง** — ตัวที่ติดกับเนื้อที่เลื่อนจริง
  ให้ทุกตัวจะได้แถบเทาหนาซ้อนกันโดยไม่ได้สื่ออะไรเพิ่ม
- **พื้นต้องทึบและต้องเปลี่ยนตามสถานะแถว** — ใช้ `group/row` ที่ `TableRow` ส่งสถานะ
  hover/selected ไปให้เซลล์ที่แช่ ไม่งั้นเซลล์นั้นจะเป็นสีเดิมอยู่ช่องเดียวทั้งแถว
- **สั่งแช่ซ้าย+ขวารวมกันเกินจำนวนคอลัมน์** ⇒ ให้ซ้ายชนะและตัดขวาทิ้ง
  (คอลัมน์เดียวถูกแช่สองฝั่งจะเพี้ยนเงียบ ๆ)
- **แถวหัวกลุ่มไม่ถูกแช่** — มันกินทั้งแถวอยู่แล้ว · ของจริงในตารางเวรตรึงเฉพาะ
  *ข้อความ*ในหัวกลุ่มไว้ซ้าย ยังไม่ได้ทำที่นี่ (ดูหัวข้อ "ค้าง")

### token ที่เพิ่ม

`--color-bg-table-header` — **แต่ละแอปใช้คนละสี** (Portal `#ededf5` · Mediwork `#f1fffd`
และอีก 2 แบบใน Mediwork เอง) จึงต้องเป็น token ให้ทับได้รายแอป ไม่ใช่เขียนตายตัว

ส่วนเส้นคั่นกับสีตัวอักษรใช้ token ที่มีอยู่แล้ว — `--color-divider-gray` (`#919eab33`)
**ตรงกับที่วัดได้เป๊ะ** · `--color-text-black` · `--color-text-primary`

## API

```tsx
<DataTable
  columns={columns}
  data={rows}
  getRowId={(r) => r.id}
  enableSelection
  isRowSelectable={(r) => r.status === "PENDING"}
  minTableWidth={900}
  pagination={{ pageIndex, pageSize, rowCount, onPageChange }}
/>
```

| prop | ค่า |
|---|---|
| `columns` `data` | `ColumnDef[]` ของ TanStack |
| `isLoading` | โครงร่างแถว · **ชนะ `error`** (refetch เบื้องหลังไม่ควรวาบ error เก่า) |
| `pagination` | แบ่งหน้าฝั่งหลังบ้าน + เลือกจำนวนแถวต่อหน้า |
| `sorting` `onSortingChange` `manualSorting` | เรียงเอง หรือให้หลังบ้านเรียง |
| `enableSelection` `isRowSelectable` 🆕 | ติ๊กแถว · จำกัดว่าแถวไหนติ๊กได้ |
| `minTableWidth` 🆕 | ความกว้างขั้นต่ำของตาราง — แคบกว่านี้เลื่อนแนวนอน |
| `columnDef.size` ⚠️ | **ความกว้างขั้นต่ำ** ไม่ใช่ความกว้างเป๊ะ |
| `renderEmpty` 🆕 | วาดสถานะว่างเอง · ได้ `{ isFiltered }` |
| `isFiltered` 🆕 | บอกตารางว่ากำลังกรองอยู่ (ตารางไม่รู้เอง) |
| `renderError` 🆕 | วาดสถานะผิดพลาดเอง · ได้ `{ error, retry }` |
| `freezeColumns` 🆕 | `{ left?: number; right?: number }` — แช่คอลัมน์เวลาเลื่อนแนวนอน |
| `onSortingChange` ⚠️ | ได้ **`SortingState` ตรง ๆ** ไม่ใช่ updater ของ TanStack |
| `onRowSelectionChange` ⚠️ | ได้ **`RowSelectionState` ตรง ๆ** เหตุผลเดียวกัน |
| `groupBy` `groupOrder` `groupLabel` 🆕 | แบ่งแถวเป็นกลุ่มใต้หัวตารางชุดเดียว — ดูหัวข้อถัดไป |
| `collapsibleGroups` `defaultCollapsedGroups` `collapsedGroups` `onCollapsedGroupsChange` 🆕 | พับ/กางกลุ่ม |
| `emptyIcon` `errorIcon` 🆕 | ไอคอนของสถานะว่าง/ผิดพลาด — ไม่ส่ง = กล่องจดหมาย / สามเหลี่ยมเตือน |
| `stickyHeader` `empty` `error` `errorSlot` `onRetry` `labels` | — |

### 🔴 ว่างเพราะกรองไม่เจอ ≠ ว่างเพราะยังไม่มีข้อมูล

สองอย่างนี้ต้องพูดคนละแบบ — *"ไม่พบผลลัพธ์ ลองแก้คำค้น"* กับ *"ยังไม่มีรายการ กดเพิ่ม"*
บอกให้ผู้ใช้ไปสร้างใหม่ทั้งที่เขาแค่กรองผิด **คือทางที่ทำให้เขาสร้างข้อมูลซ้ำ**

ตารางไม่รู้เองว่ากำลังถูกกรองอยู่ เพราะช่องค้นหา/ตัวกรองอยู่นอกตัวมัน ⇒ ผู้เรียกต้องบอกผ่าน `isFiltered`

```tsx
renderEmpty={({ isFiltered }) => isFiltered ? <NoMatch /> : <FirstRun />}
renderError={({ error, retry }) => <ApiError err={error} onRetry={retry} />}
```

`renderError` ต่างจาก `errorSlot` ตรงที่**ส่ง `error`/`retry` มาให้** ไม่ต้อง closure เอง
⇒ แยกเป็น component ที่ใช้ซ้ำได้จริง · render prop ชนะ slot เมื่อส่งมาทั้งคู่

## จัดกลุ่มแถว (`groupBy`)

แยกแถวเป็นกลุ่ม — ประจำ/พาร์ตไทม์ · ตามวันที่ · ตามวิชาชีพ — **ใต้หัวตารางชุดเดียว**

```tsx
<DataTable
  columns={columns}
  data={roster}
  groupBy={(p) => (p.isPartTime ? "partTime" : "fullTime")}
  groupOrder={["fullTime", "partTime"]}
  groupLabel={({ key, count }) => `${t(`group.${key}`)} (${count})`}
/>
```

### สำรวจของจริงก่อน — มี 8 ที่ที่จัดกลุ่มอยู่แล้ว ทำกันคนละแบบทั้ง 8

| ที่ไหน | แบ่งตาม | ทรงที่ใช้วันนี้ |
|---|---|---|
| คำขอ 5 หน้า (ลา · ทำงาน · หยุด · แลกเวร · โอนเวร) | วันที่ | ✅ หัวชุดเดียว + แถวหัวกลุ่มใน `<tbody>` |
| roster ฝั่ง Mediwork | ประจำ/พาร์ตไทม์ | ❌ **2 ตาราง หัวซ้ำ 2 ชุด** |
| roster ฝั่ง MediHR | ประจำ/พาร์ตไทม์ | ❌ 2 section หัวซ้ำ 2 ชุด |
| ตารางเวร | วิชาชีพ → ประเภทการจ้าง (2 ชั้น) | พับได้ · ไม่ใช่ `<table>` |

**สิ่งที่ผู้ใช้ขอคือทรงของกลุ่มแรก** — และเป็นทรงที่ถูก: หัวคอลัมน์ชุดที่สองกลางจอ
อ่านเป็น "ตารางใหม่" ไม่ใช่ "หัวข้อย่อยของตารางเดิม"

### 🔴 บั๊กเดียวกันทั้ง 5 หน้า: `colSpan` เขียนเลขตายตัว

```tsx
<TableCell colSpan={6}>   // leave · work
<TableCell colSpan={5}>   // day-off · swap
<TableCell colSpan={7}>   // transfer
```

วันที่ใครเพิ่มคอลัมน์ แถบหัวกลุ่มจะสั้นกว่าตารางแล้วมีช่องโหว่ท้ายแถว
**โดยไม่มีอะไรฟ้อง** — ตัวนี้นับจาก `getVisibleLeafColumns().length` เสมอ
(คอลัมน์ติ๊กเลือกนับรวมด้วย) มี unit test ล็อกทั้ง 3 เคส

### 🔴 สีแถบหัวกลุ่มไม่ตรงกันอยู่แล้ววันนี้

`#F1FFFD` (ลา · แลกเวร · โอนเวร) กับ `#F5F6F7` (ทำงาน · หยุด) — สองสีนี้อยู่ใน
ผลิตภัณฑ์เดียวกันคนละหน้า

DS ใช้ `bg-table-header` ตัวเดียว เพราะหัวกลุ่ม **ก็คือหัว** ไม่ใช่ข้อมูล

| ตัวเลือกที่ไม่เลือก | เหตุผล |
|---|---|
| `bg/subtle` | เป็นสี **hover ของแถว** — หัวกลุ่มจะดูเหมือนแถวที่ถูกชี้อยู่ |
| `brand/subtle` | บน **Medimatch** มันเท่ากับ `bg/surface` พอดี — แถบหายไปเลย (§9 ข้อ 5 ของ `CLAUDE.md`) |

### กติกาที่ยกมาจากกลุ่มตัวเลือกใน `ComboBox`

ใช้ `form/group-options.ts` **ตัวเดียวกัน** ⇒ "จัดกลุ่ม" แปลว่าเรื่องเดียวกันทั้งระบบ

- ไม่ส่ง `groupOrder` = เรียงตาม**ลำดับที่เจอครั้งแรก**ในข้อมูล ไม่ใช่ตามตัวอักษร
- กลุ่มที่ไม่อยู่ใน `groupOrder` **ต่อท้าย ไม่ถูกทิ้ง** (ทิ้ง = แถวหายจากจอเงียบ ๆ)
- แถวที่ `groupBy` คืน `null` อยู่**บนสุดและไม่มีแถบหัว**

### สามข้อที่ต้องรู้

1. **`groupBy` คืนคีย์ ไม่ใช่คำที่จะแสดง** — คืนคำแปลตรง ๆ กลุ่มจะแตกเป็นคนละกลุ่ม
   ทันทีที่สลับภาษา · ข้อความมาจาก `groupLabel` ซึ่งรับ `count` มาให้แล้ว
2. **จัดกลุ่มหลังเรียงเสมอ** — ทำงานบน row model ที่ TanStack เรียง/แบ่งหน้าให้แล้ว
   ไม่งั้นกลุ่มจะไม่ตรงกับสิ่งที่ตารางกำลังแสดง
3. **พับกลุ่มไม่ยกเลิกการติ๊กเลือก** — แถวที่เลือกไว้ยังนับอยู่ในตัวเลข "เลือกแล้ว N"
   ทั้งที่มองไม่เห็น · ตั้งใจ พับคือการซ่อนชั่วคราว ไม่ใช่การถอนสิ่งที่ผู้ใช้เลือกไว้

### จุดสีหน้าป้ายเป็นของผู้เรียก

`groupLabel` คืน element ได้ ⇒ DS ไม่ต้องรับสีดิบเข้ามาเป็น prop

```tsx
groupLabel={({ key, count }) => (
  <span className="flex items-center gap-2">
    <span className={cn("size-2 rounded-full", key === "fullTime" ? "bg-success-green-600" : "bg-brand")} />
    {t(`group.${key}`)} ({count})
  </span>
)}
```

## 🔴 สามอย่างที่แก้จากผลสำรวจ

### 1. `size` = ความกว้าง**ขั้นต่ำ** ไม่ใช่ความกว้างเป๊ะ

ของจริงทุกแอปเขียน `minWidth: '200px'` — **22/41 ไฟล์ มากกว่าความสามารถอื่นทุกตัว**
เดิม DS แปลงเป็น `width` เป๊ะ ⇒ คอลัมน์ไม่ขยายตามตาราง เหลือช่องว่างด้านขวาเวลาจอกว้าง

**วัดจริงในเบราว์เซอร์** — ตั้ง `Name: 260` · `Role: 100` · `Email` ไม่ตั้ง บนกล่องกว้าง 1166:

```
Name   จริง 555  min 260px   ← ขยายเกินขั้นต่ำได้
Email  จริง 398  ไม่ตั้ง
Role   จริง 213  min 100px
ตาราง 1166 = กล่อง 1166      ← เต็มพอดี ไม่เหลือขาว
```

⚠️ **TanStack ตั้ง `size: 150` ให้ทุกคอลัมน์เป็นค่าเริ่มต้น** — อ่านจาก `columnDef.size`
ตรง ๆ ไม่ได้ เพราะจะได้ 150 มาแม้ผู้เรียกไม่ได้สั่ง แล้วทุกคอลัมน์โดนยัด min-width 150px
`DataTable` จึงอ่านจาก `columns` ที่ส่งเข้ามาโดยตรง

### 2. `isRowSelectable` — ติ๊กได้เฉพาะบางแถว

ของจริงบน Mediwork ต้องการทุกหน้าคำขอ: ติ๊กได้เฉพาะใบที่ยัง "รออนุมัติ" ใบที่อนุมัติ/
ปฏิเสธไปแล้วต้องเห็นในตารางแต่ทำอะไรไม่ได้ — **วันนี้ 6 ฟีเจอร์ส่ง `pendingCount` เข้าไปเอง ซ้ำกันหมด**

**select-all นับจากแถวที่ติ๊กได้เท่านั้น** — ถ้านับจากแถวทั้งหมด หน้าที่มีแถวติ๊กไม่ได้ปนอยู่
จะ**ค้างเป็นขีดกลางตลอดไป ไม่มีทางขึ้นเป็น "เลือกครบ" เลย**

⚠️ `table.setRowSelection` ครั้งเดียวทั้งก้อน — วนเรียก `toggleSelected` ทีละแถวจะคิดจาก
state เดิมที่ยังไม่ re-render ทุกครั้ง แล้วตัวสุดท้ายทับตัวก่อนหน้า

### 3. ตัวนับ "เลือกแล้ว N" ต้องขึ้นแม้ไม่มีแบ่งหน้า

เดิมตัวนับอยู่ในแถบแบ่งหน้าเท่านั้น ⇒ **ตารางที่เลือกแถวได้แต่ไม่มีแบ่งหน้าจะติ๊กแล้วเงียบสนิท**

ของจริง: เลือกได้ **11** ตาราง · มีแบ่งหน้า **6** ⇒ ~5 ตารางเคยเงียบ
การเลือกที่ไม่มีผลตอบกลับคือการเลือกที่ผู้ใช้ไม่มั่นใจว่าติดหรือยัง

⇒ หลุดจากชุดไอคอนที่ทีมใช้จริง · ผู้ใช้ชี้ไปที่ไฟล์ MediHR ให้ยึดตามนั้น

| ที่ใช้ | ไอคอน | ห่อ `<Icon>` ไหม |
|---|---|---|
| หัวกลุ่มกางอยู่ | `ExpandMoreFilled` | ✅ `Size=Inherit` (16) |
| หัวกลุ่มพับอยู่ | `ChevronRightFilled` | ✅ `Size=Inherit` |
| ปุ่มเปลี่ยนหน้า | `ChevronLeftFilled` / `ChevronRightFilled` | ✅ `Size=Small` (20) |
| ลูกศรช่องเลือกจำนวนแถว | `ExpandMoreFilled` | ✅ `Size=Inherit` |
| เรียงน้อย→มาก | **`arrow-up-sm`** ย่อเป็น 16 | ❌ ใช้ตรง ๆ ตามที่ไฟล์ HR ใช้ |
| เรียงมาก→น้อย | **`arrow-up-sm` ตัวเดิม หมุน 180°** | ❌ |

🔴 **ไลบรารีไม่มี `arrow-down-sm`** — กวาดทั้งไฟล์ HR (248 component, 1,045 `<Icon>`) แล้ว
พบไอคอนตระกูลลูกศร/chevron ครบทุกตัวที่มี · ตัวลงจึงเป็นตัวขึ้นหมุน 180° ซึ่งเป็นภาพเดียวกันเป๊ะ

⚠️ **ช่องว่างเดียวที่เหลือ: ไม่มีไอคอน "เรียงได้ 2 ทาง" (unfold)** ⇒ สถานะ `Sort=sortable`
ประกอบจาก `ExpandLessFilled` + `ExpandMoreFilled` ซ้อนกันในกล่อง 16px
**ไม่ได้วาดเวกเตอร์ใหม่** เพราะนั่นคือกลับไปสู่ปัญหาเดิม · ถ้าทีมออกแบบเพิ่ม
`UnfoldMoreFilled` เข้าไลบรารีเมื่อไหร่ ให้สลับมาใช้ตัวนั้น

✅ **ฝั่งโค้ดไม่ต้องแก้** — lucide `ArrowUp`/`ArrowDown` เป็นลูกศรมีหางอยู่แล้ว
และ `ChevronsUpDown` คือ "เรียงได้ 2 ทาง" ตรงกับที่ประกอบไว้ใน Figma

📌 `<Icon>` มี 8 variant (`Size` 4 × `Type` 2) และ swap ไอคอนข้างในผ่าน property
`Icon Instance` ซึ่งเป็น **INSTANCE_SWAP ที่รับ node id ไม่ใช่ component key**
(ส่ง key เข้าไปจะได้ `Property value is incompatible with component property type`)

📌 **`<Group row>` กว้าง 440 ในหน้า Figma แต่ instance ในเฟรมอ้างอิงเป็น `FILL` = 700**
ตั้งใจ — ตัว atom ต้องแคบพอไม่ให้ทับคอลัมน์เฟรมอ้างอิงที่ x=520 ส่วนของจริงกินเต็มตารางเสมอ

📌 **สีจุดผูก `success/default` ไว้เป็นค่าเริ่มต้น แต่เป็นของแต่ละกลุ่ม** —
เฟรมอ้างอิง override เป็น `brand/default` ให้พาร์ตไทม์ · เขียนไว้ใน description ของ component แล้ว

ทุกค่าผูก variable ไม่มีสีดิบ — เพิ่ม variable ใหม่ 6 ตัวใน collection `Color`
(`bg/table-header` `bg/subtle` `divider/gray` `text/black` `overlay/hover` `overlay/press`)

📌 **`bg/table-header` ตั้งค่าต่างกันตามโหมด** — Portal `#ededf5` · Mediwork `#f1fffd`
อีก 2 แอปใช้ค่าของ Portal ไปก่อน (ยังไม่ได้วัด)

🔴 **มีเฟรม "ว่าง" สองอัน โดยตั้งใจ** — designer ที่เห็นแค่อันเดียวจะเขียนข้อความเดียว
ใช้ทั้งสองกรณี แล้วผู้ใช้ที่กรองผิดจะถูกชวนไปสร้างข้อมูลซ้ำ

⚠️ **ไม่ได้ทำตารางทั้งใบเป็น component** — ทำเป็นเฟรมอ้างอิงแทน เพราะจำนวนคอลัมน์/แถว
ต่างกันทุกหน้า · component ที่ต้องแก้โครงทุกครั้งที่ใช้ ไม่ได้ช่วยอะไรนอกจากทำให้แก้ยากขึ้น

## สถานะว่าง/ผิดพลาด = `EmptyState` · `ErrorState` ตัวเดียวกับที่แอปใช้

ตารางเคยประกอบสถานะผิดพลาดเอง และเคยส่ง `EmptyState` แค่ `title`/`description`
⇒ **ไม่มีป้ายไอคอนเลย** · สองสถานะนี้ในตารางจึงหน้าตาไม่เหมือนที่อื่นในจอเดียวกัน
ทั้งที่เรียก component ตัวเดียวกันอยู่

**Figma เป็นแบบเดียวกันเป๊ะ** — 3 เฟรมสถานะบนหน้า `DataTable` ใช้ `<State media>`
จากหน้า `EmptyState` แล้ว (ข้ามหน้าได้ในไฟล์เดียวกัน)

ตอนนี้ส่งไอคอนให้ด้วย (`Inbox` / `AlertTriangle` เป็นค่าตั้งต้น) — เปลี่ยนได้ผ่าน
`emptyIcon`/`errorIcon` · ควรส่งให้ตรงกับสิ่งที่ตารางแสดง เพราะ "ยังไม่มีคำขอ" กับ
"ยังไม่มีบุคลากร" เป็นความว่างคนละอย่าง

## ค้าง

- **ยังไม่ย้ายแอปไหนมาใช้** — Mediwork 11 ชุด · อีก 3 แอป 12 จุด (ผู้ใช้เคาะให้ทำ DS ก่อน)
- 🟡 `stickyHeader` + `minTableWidth` พร้อมกันยังไม่ได้พิสูจน์ — `Table` ห่อ `overflow-auto`
  ของตัวเองอยู่แล้ว การมีกล่อง scroll ซ้อนกันอาจทำให้หัวตารางไม่ติดจริง
- 🟡 ยังไม่มีแถบปฏิบัติการหมู่ (bulk action bar) ที่ Mediwork มี — วันนี้เป็น modal แยกของแต่ละฟีเจอร์
- 🟡 **Mediwork ยังไม่มี theme ทับ** `--color-bg-table-header` ⇒ ถ้าเอา DS ไปใช้ที่นั่นจะได้พื้นของ Portal (`#ededf5`) ไม่ใช่ `#f1fffd` ของตัวเอง
  (Figma มีโหมดแยกแล้ว · **ฝั่ง CSS ยังเป็นค่าเดียวใน `theme.css`** — ไปพร้อมกับการย้าย token)
- 🟡 **หัวตารางกับหัวกลุ่มแรกใช้สีเดียวกัน** ⇒ ติดกันเป็นแถบเดียว 89px คั่นด้วยเส้น 1px
  อ่านออกอยู่ (ดูภาพใน Storybook) แต่ถ้า designer อยากให้แยกกว่านี้ ต้องมี token ที่สาม —
  ยังไม่เพิ่มเพราะไม่มีค่าที่วัดมาจากของจริงมารองรับ
- 🟡 **จัดกลุ่ม 2 ชั้นยังทำไม่ได้** — ตารางเวรทำอยู่ (วิชาชีพ → ประเภทการจ้าง) แต่มันไม่ใช่
  `<table>` จึงยังไม่ใช่ผู้ใช้ของ DS · ทำเมื่อมีคนย้ายจอนั้นมาจริง
- 🟡 **หัวกลุ่มไม่ตรึงซ้ายเวลาเลื่อนแนวนอน** — ของจริงในตารางเวรตรึง *ข้อความ* ในหัวกลุ่ม
  ไว้ที่ `left: 12` (`StaffGroupHeader`) · ที่นี่หัวกลุ่มเลื่อนไปกับตาราง ⇒ เลื่อนไปไกล ๆ
  แล้วจะไม่รู้ว่าอยู่กลุ่มไหน · ยังไม่ทำเพราะยังไม่มีใครย้ายจอนั้นมาใช้ DS
- 🟡 **แช่คอลัมน์ยังไม่ได้วัดบนจอแคบ** — วัดที่ 1280 อย่างเดียว · ที่ 375 คอลัมน์ที่แช่
  ทั้งสองฝั่งอาจกินพื้นที่จนเนื้อที่เลื่อนได้เหลือนิดเดียว ยังไม่มีด่านกัน
- 🟡 **ไม่มี select-all รายกลุ่ม** — 5 หน้าคำขอจัดกลุ่มตามวันที่และติ๊กเลือกได้ทั้งคู่
  แต่ "เลือกทั้งวันนี้" ยังไม่มีที่ไหน ⇒ ไม่ใส่ในรอบนี้
- 🟡 **`onRowClick` ส่งลำดับ "ตามที่เห็นบนจอ"** ซึ่งขยับเมื่อพับกลุ่ม/เปลี่ยนการเรียง —
  คงพฤติกรรมเดิมไว้เพื่อไม่ให้ต่างกันระหว่างโหมดจัดกลุ่มกับไม่จัดกลุ่ม
  แต่ตัวเลขนี้แทบไม่มีประโยชน์กับผู้เรียก · ควรเป็น `row.index` ทั้งคู่ในรอบทำความสะอาด
