# SearchSelect

ช่อง **ค้นหา-แล้วเลือกหนึ่งค่า** ที่ไม่ผูก Radix Popover — ทางเลือกของ `ComboBox typeahead` /
`EntityAutocomplete` สำหรับที่ที่แผงแบบ portal พังโดยที่เราแก้ไม่ได้

```tsx
<SearchSelect<Person>
  label="ค้นหาผู้ใช้ในระบบ"
  placeholder="พิมพ์ชื่อหรืออีเมล..."
  options={search.options}
  optionsLoading={search.isSearching}
  value={selected}
  onChange={setSelected}
  onSearch={setTerm}          // debounce ที่ผู้เรียก
  getOptionValue={(p) => String(p.userId)}
  getOptionLabel={(p) => p.fullName}
  getOptionDescription={(p) => [p.email, p.roleName].filter(Boolean).join(" · ")}
  minChars={2}
  hintText="พิมพ์อย่างน้อย 2 ตัวอักษรเพื่อค้นหา"
  emptyText="ไม่พบข้อมูล"
/>
```

## ทำไมมีตัวนี้ ทั้งที่มีสองตัวนั้นอยู่แล้ว

วันที่ 2026-08-19/20 จอ *เพิ่มบุคลากร* ของ Mediwork ชนบั๊กของ **สามชั้นใต้ Radix Popover** ครบทั้งสาม
ในจอเดียว:

| # | ชั้น | อาการ | แก้ได้ไหม |
|---|---|---|---|
| ① | `react-focus-scope` | `Dialog` กับ `Popover` ได้ **คนละก๊อป** (แพ็กเกจเก็บ stack ไว้ระดับ module) ⇒ `Dialog` ดึงโฟกัสกลับจากแผงที่ถูก portal ออกไป ⇒ **พิมพ์ไม่ติดเลย** แผงเปิดสวย ตัวเลือกคลิกได้ ไม่มี error | ✅ ยกเวอร์ชันให้ทั้งตระกูลเดินพร้อมกัน (มี guard คุมแล้ว) |
| ② | `react-popper` 1.3.x | `setState` ใน cleanup ของ `useLayoutEffect` ⇒ แผงหนึ่ง unmount ชน mount = `Maximum update depth` | ⚠️ ได้ด้วย `overrides` → 1.2.8 (guard คุม) |
| ③ | `@floating-ui/react-dom` | ยิง `setState` ตอน React **ถอด ref** ระหว่างลบ subtree (`safelyDetachRef`) ⇒ `Maximum update depth` | ❌ **ไม่มีเวอร์ชันไหนแก้** — เทียบ dist แล้ว `2.1.9` เหมือน `2.1.8` เป๊ะตรงจุดนั้น |

③ เป็นเหตุผลที่ต้องมีคอมโพเนนต์นี้: **ไล่เวอร์ชันต่อไม่มีทางจบ** ⇒ ทางออกคือไม่ใช้ชั้นนั้นเลย

## สิ่งที่ต่างจากของเดิม — ข้อเดียว

**แผงอยู่ในต้นไม้ DOM เดิม** (`absolute` ใน `relative` ของตัวเอง) ⛔ ไม่ `Portal`
⇒ ไม่มี Radix Popover · ไม่มี popper · ไม่มี floating-ui ⇒ บั๊กทั้งสามหมดสิทธิ์เกิด
**โดยโครงสร้าง ไม่ใช่โดยการเลือกเวอร์ชันให้ถูก**

หน้าตายังเป็นของ DS — ยืม `FloatingFieldShell` + `fieldShapeClasses` ตัวเดียวกับ `Input`/`Select`
(สองไฟล์นั้นไม่ผูก Radix) ⇒ ป้ายลอย · ขอบ · ระยะ · บรรทัดข้อความใต้ช่อง เหมือนช่องอื่นทั้งระบบ

## ราคาที่รับไว้ — อ่านก่อนเลือกใช้

- 🔴 **แผงถูก clip ได้** ถ้าบรรพบุรุษมี `overflow: hidden`/`auto` — นี่คือเหตุผลที่ไลบรารีทั่วโลก portal กัน
  ⇒ อย่าวางในกล่องที่ตัดขอบแล้วสูงไม่พอ · ในโมดัลและแถบขอบเขต (ที่เราใช้) พื้นที่พอและไม่ตัดขอบ
- **ไม่พลิกด้านอัตโนมัติ** — เปิดลงล่างเสมอ
- ⛔ **ไม่รองรับเลือกหลายอัน** — ต้องการหลายค่าใช้ `ComboBox multiple` ตามเดิม
- ของที่ Radix เคยให้ฟรีแล้วต้องทำเอง: ปิดเมื่อคลิกข้างนอก · คืนโฟกัสหลังเลือก · คีย์บอร์ด ↑↓/Enter/Esc

## Esc — จุดที่ยากที่สุด และเป็นความรู้ที่ใช้ได้ทั้ง repo

`Dialog` ของ Radix ฟัง `keydown` ที่ **`document` ด้วย `{ capture: true }`**
(`use-escape-keydown/dist/index.mjs:12`) · capture ไล่ `window` → `document` → … → target
⇒ handler ของมัน **ทำงานก่อน** อะไรที่อยู่บน element ของเรา ⇒ `stopPropagation` ใน `onKeyDown`
**สายเกินไปเสมอ** (เทสจับได้: แผงปิดแต่โมดัลปิดตามไปด้วย = ผู้ใช้เสียฟอร์มที่กรอกค้าง)

⇒ ทางเดียวที่ชนะคือดักที่ **`window` แบบ capture** (ถึงก่อน `document`) แล้ว
`stopImmediatePropagation()` · ผูกเฉพาะตอนแผงเปิด ⇒ Esc ครั้งถัดไปถึงโมดัลตามปกติ
⛔ ไม่กลืน Esc ของคนอื่นทิ้ง

## สถานะการพิสูจน์

| ข้อ | วิธีพิสูจน์ | ผล |
|---|---|---|
| พิมพ์ได้เมื่ออยู่ในโมดัล | **เบราว์เซอร์จริง** (Storybook · story `InDialog` · StrictMode) | ✅ พิมพ์ `carm` → ช่องได้ค่า · โฟกัสอยู่ในช่อง · กรองเหลือ `Carmen Diaz` · แผงอยู่ใน `[role="dialog"]` จริง |
| Esc ปิดแค่แผง ไม่ปิดโมดัล | **เทส jsdom เท่านั้น** | ⚠️ แดงก่อนแก้ · เขียวหลังแก้ ⇒ กลไกถูก · **แต่ยังไม่ได้ยืนยันในเบราว์เซอร์** — เครื่องมือที่ใช้อยู่ส่งคีย์ไปไม่ถึงหน้า (probe บน `window`/`document` ไม่เห็นอีเวนต์เลย) ⇒ ต้องให้คนกดจริง |
| สลับสองช่องไม่วน | ยังไม่วัด | ⚠️ story `TwoFieldsSideBySide` เตรียมไว้แล้ว · ตัวนี้ไม่มี popper/floating-ui ⇒ ไม่มีชั้นที่เคยวน แต่ **ยังไม่ได้กดจริง** |

| วันที่ | ตัดสิน | เหตุผล | ราคาที่รับ |

| 2026-08-20 | แผงไม่ portal | ตัดบั๊กสามตัวที่ขึ้นกับเวอร์ชันออกทั้งหมด | แผงถูก clip ได้ · ไม่พลิกด้าน |
