## สองทางที่ไม่เหมือนกัน

ต่างกันที่**ที่มาของข้อมูล** ไม่ใช่หน้าตาผลลัพธ์ — ออกมาเหมือนกันเป๊ะ

| prop | ใช้เมื่อ | มีที่ไหน |
|---|---|---|
| `groups` | หลังบ้านคืนข้อมูล**เป็นกลุ่มมาแล้ว** | `ComboBox` |
| `groupBy` | ได้รายการ**แบน** แล้วอยากแบ่งตามฟิลด์บางตัวเอง | ทั้งสองตัว |

ของจริงมีทั้งสองแบบ — `departmentSubUnitService.getGrouped()` คืนหน่วยงานแยกตามแผนกมาให้แล้ว
(→ `groups`) ส่วนผลค้นหาคนมาเป็นรายการแบน (→ `groupBy`)

**ส่งมาทั้งคู่ `groups` ชนะ** — ของที่ระบุมาตรง ๆ ชนะของที่คำนวณเอาเสมอ

## ใช้ยังไง

```tsx
// รายการแบน → แบ่งตามแผนก
<EntityAutocomplete<Person>
  options={people}
  groupBy={(p) => p.department}
  getOptionValue={(p) => p.id}
  getOptionLabel={(p) => p.name}
  onSearch={fetchPeople}
/>

// ล็อกลำดับหัวข้อเอง
<EntityAutocomplete groupBy={(p) => p.department} groupOrder={["ICU", "ER"]} … />
```

| prop | ค่า |
|---|---|
| `groupBy` | `(item) => string \| null \| undefined` — คืน `null` = ไม่เข้ากลุ่มไหน |
| `groupOrder` | `string[]` — ไม่ส่ง = ลำดับที่เจอครั้งแรก |

---

## 🔴 สามอย่างที่ตัดสินไว้แล้วและมีเหตุผล

### 1. ลำดับเริ่มต้น = ลำดับที่เจอครั้งแรก ไม่ใช่เรียงตามตัวอักษร

ผลค้นหาส่วนใหญ่มาจากหลังบ้านที่**จัดอันดับความเกี่ยวข้องมาแล้ว** เรียงตามตัวอักษรทับ
= ทำลายอันดับนั้นเงียบ ๆ โดยที่ผู้เรียกไม่รู้ตัว

อยากได้ลำดับตายตัวส่ง `groupOrder` มา

### 2. กลุ่มที่ไม่อยู่ใน `groupOrder` ต่อท้าย ไม่ถูกทิ้ง

ทิ้งไป = **ตัวเลือกหายจากจอโดยไม่มีใครรู้** ซึ่งเป็นความผิดพลาดที่หาไม่เจอ
ส่วนต่อท้ายเป็นความผิดพลาดที่เห็นทันที

พิสูจน์สด — `groupOrder={["Pediatrics", "Oncology"]}` บนข้อมูล 4 แผนก:

```
## Pediatrics   ← ตามที่สั่ง
## Oncology     ← ตามที่สั่ง
## Cardiology   ← ต่อท้าย ไม่หาย
## Radiology    ← ต่อท้าย ไม่หาย
```

### 3. รายการที่ไม่เข้ากลุ่มไหนอยู่ก้อนแรกและไม่มีหัวข้อ

ตั้งใจให้อยู่บนสุด เพราะปกติคือรายการที่ตรงที่สุดหรือเพิ่งใช้ล่าสุด

⚠️ ก้อนนี้**ไม่ห่อ `CmdkRoot.Group`** — ถ้าห่อ cmdk จะเว้นที่ให้หัวข้อว่างไว้
กลายเป็นช่องว่างลอย ๆ บนสุดของลิสต์

---

## ⚠️ จัดกลุ่มจากผลหน้านี้เท่านั้น ไม่ใช่ทั้งฐานข้อมูล

`groupBy` ทำงานกับ `options` ที่อยู่ในมือ**ตอนนั้น** — ค้นแล้วได้ 20 แถวจาก 3 แผนก
หัวข้อจะมี 3 อัน **ไม่ใช่ทุกแผนกที่มีอยู่จริง**

ถ้าหน้าจอต้องโชว์หัวข้อครบทุกกลุ่มเสมอ (เช่นให้เห็นว่าแผนกไหน "ไม่มีใครเลย")
ต้องให้หลังบ้านคืนกลุ่มว่างมาด้วย แล้วใช้ `groups` แทน

## ผลที่วัดได้จริง

เปิดลิสต์จริงในเบราว์เซอร์แล้วอ่านลำดับ DOM ของหัวข้อกับแถว

| เคส | ผล |
|---|---|
| `ComboBox multiple` `groupBy` | 3 หัวข้อ · 6 แถว ✅ |
| ไม่เข้ากลุ่ม (`null`) | "React (ใช้ล่าสุด)" อยู่บนสุด **ไม่มีหัวข้อ** แล้วตามด้วย 3 กลุ่ม ✅ |
| `ComboBox multiple` `groups` | 2 หัวข้อ · 6 แถว ✅ ไม่ถูกกระทบ |
| `EntityAutocomplete` `groupBy` | 4 หัวข้อ เรียงตามที่เจอ ✅ |
| `EntityAutocomplete` `groupOrder` | 2 ตัวแรกตามสั่ง · อีก 2 ต่อท้าย ✅ |

**การกรองยังถูกด้วย** — พิมพ์ค้นแล้วหัวข้อของกลุ่มที่ไม่มีผลลัพธ์**หายตามไปเอง**
(เป็นจุดที่ลิสต์แบบกลุ่มพังบ่อยสุด — cmdk จัดการให้แล้ว ไม่ต้องเขียนเอง)

```
ก่อนพิมพ์  Library · Framework · Compiler   6 แถว
พิมพ์ "re"      Library · Framework           2 แถว
พิมพ์ "svelte"  Compiler                      1 แถว
```

# ค่าที่ล็อกไว้ (`locked` / `isOptionLocked`)

ค่าตั้งต้นที่ระบบผูกมาให้และผู้ใช้ถอดออกไม่ได้ — เช่นหน่วยงานประจำ

```tsx
// ComboBox: ทำเครื่องหมายที่ตัวเลือก
options={[{ value: "icu", label: "หอผู้ป่วยหนัก (ประจำ)", locked: true }, …]}
defaultValue={["icu", "er"]}

// EntityAutocomplete: ตอบเป็นฟังก์ชัน เพราะรายการเป็น object อะไรก็ได้
isOptionLocked={(p) => p.isHome}
```

## 🔴 ล็อกแปลว่าปิด 3 ทาง ไม่ใช่ซ่อนปุ่มเดียว

ทางถอดออกมี 3 ทาง — ปิดไม่ครบเท่ากับไม่ได้ปิด

| ทาง | ปิดยังไง |
|---|---|
| กดปุ่ม `×` บน chip | ไม่ render ปุ่ม |
| กดซ้ำที่แถวในลิสต์ | `toggle`/`selectItem` คืนออกก่อน |
| ปุ่ม **ล้างทั้งหมด** | กรองเก็บตัวที่ล็อกไว้ |

ทางที่ 3 คือทางที่ลืมง่ายสุด — ล้างหมดจริงทำให้อีกสองด่านไม่มีความหมายเลย

## 🔴 ต้องเห็นว่าล็อก ไม่ใช่แค่กดไม่ได้

ซ่อนปุ่ม `×` เฉย ๆ = ผู้ใช้เห็น chip ที่ลบไม่ออกแล้ว**นึกว่าจอเสีย**

ตัวเริ่มต้นจึงบอก 2 ชั้น: **chip เปลี่ยนสี** (`neutral` แทน `primary`) **+ ไอคอนกุญแจ**
ส่วนแถวในลิสต์ใช้**กุญแจแทนเครื่องหมายถูก** — มันถูกเลือกอยู่แล้วโดยนิยาม
สิ่งที่ผู้ใช้ต้องรู้คือ "ถอดไม่ได้" ไม่ใช่ "เลือกอยู่"

ยกมาจากของจริง — `SubUnitMultiSelect` บน Portal ทำแบบนี้อยู่แล้ว
(`variant={locked ? "Normal" : "Primary"}` + `icon={<Lock/>}`)

## ⚠️ สามข้อที่พลาดง่าย

1. **ไม่ได้ทำให้ถูกเลือกให้เอง** — ต้องใส่ใน `defaultValue`/`value` ด้วย
   prop นี้ตอบว่า *"ถอดออกได้ไหม"* ไม่ใช่ *"ต้องมีไหม"*
2. **ไม่มีในโหมดเลือกอันเดียว** (`ComboBox` · `EntityAutocomplete` ที่ไม่ใส่ `multiple`)
   เพราะการเลือกทับคือการ*เปลี่ยนค่า* ไม่ใช่การถอดออก — ล็อกไว้จะกลายเป็นช่องที่แก้ไม่ได้เลย
   ใช้ `disabled` แทน (`isOptionLocked` ถูกเมินเงียบในโหมดนี้โดยตั้งใจ)
3. **แถวที่ล็อกยังค้นเจอและอ่านออก** — ไม่ได้ใช้ `disabled` ของ cmdk
   เพราะมันจะพาแถวหลุดจากผลค้นหาและจางจนอ่านไม่ออก

## ผลที่วัดได้จริง

กดจริงในเบราว์เซอร์ทีละทาง ทั้งสอง component

| ทาง | `ComboBox multiple` | `EntityAutocomplete` |
|---|---|---|
| ปุ่ม `×` บน chip ที่ล็อก | ไม่มีปุ่ม ✅ | ไม่มีปุ่ม ✅ |
| ปุ่ม `×` บน chip ปกติ | มีปุ่ม ✅ | มีปุ่ม ✅ |
| กดแถวที่ล็อกในลิสต์ | chip 2 → 2 ✅ | chip 2 → 2 ✅ |
| ปุ่มล้างทั้งหมด | เหลือตัวที่ล็อก 1 ✅ | เหลือตัวที่ล็อก 1 ✅ |

# วาดแถวเอง (`renderOption`)

`renderOption` ได้สถานะ **3 ตัว** ไม่ใช่ตัวเดียว (เดิมมีแค่ `selected`)

```tsx
renderOption={(opt, { selected, locked, disabled }) => …}
renderChip={(opt, { locked }) => …}
```

| | ความหมาย |
|---|---|
| `selected` | ถูกเลือกอยู่ |
| `locked` | เลือกอยู่**และถอดออกไม่ได้** |
| `disabled` | กดไม่ได้ — ปิดใช้งานมาเอง หรือเลือกครบ `maxItems` แล้ว |

`locked` ต่างจาก `disabled` ตรงที่**ถูกเลือกอยู่เสมอ** — `disabled` คือกดไม่ได้เพราะ
*เลือกไม่ได้* ส่วน `locked` คือกดไม่ได้เพราะ*เอาออกไม่ได้*

⚠️ พอมี `locked` แล้ว แถวที่วาดเองซึ่งรู้แค่ `selected` จะ**แสดงไม่ได้เลยว่าตัวไหนล็อก**
— นี่คือเหตุผลที่ขยาย state ไม่ใช่แค่ความสะดวก

type อยู่ที่ `form/option-row.ts` ที่เดียว ทั้งสาม component ใช้ร่วมกัน —
ถ้าแต่ละตัวส่งคนละทรง คนเขียนแถวเองจะต้องจำว่า component ไหนให้อะไรบ้าง

## ค้าง

- **`ComboBox`/`EntityAutocomplete` ยังไม่มี component ของตัวเองใน Figma** —
  หัวกลุ่มกับแถวที่ล็อกอยู่บนหน้า `Select` และ chip ในเฟรมอ้างอิงเป็นของ**วาดมือ**
  (ยังไม่มี component ของ `Chip` ในไฟล์นี้) ⇒ ดริฟต์ได้ถ้าไม่ทำเป็น component
- `groupBy` ที่คืนค่าต่างกันระหว่าง render จะจัดกลุ่มใหม่ทุกครั้ง — ห่อ `useCallback` เองถ้าลิสต์ยาว
- ยังไม่ได้เอาไปแทน `SubUnitMultiSelect` ของ Portal ซึ่งเขียนเองทั้งตัวเพื่อทำเรื่องนี้
- 🟡 **"ไม่มีค่า" ยังไม่ตรงกันทั้งระบบ** — `ComboBox`/`EntityAutocomplete` = `null` แต่ `Select` = `""`
