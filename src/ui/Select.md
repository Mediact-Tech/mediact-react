## API

```tsx
<Select
  label="หน่วยงาน"
  options={[{ value: "5734", label: "หอผู้ป่วยใน" }]}
  value={v}
  onChange={setV}
  isLoading={isFetching}   // ⚠️ ไม่ใช่ disabled
/>
```

| prop | ค่า | ค่าเริ่มต้น |
|---|---|---|
| `options` | `{ value, label, disabled? }[]` — หรือส่ง `children` เป็น `<SelectItem>` เองเมื่อต้องจัดกลุ่ม | — |
| `value` / `defaultValue` / `onChange` | ควบคุมเองหรือปล่อยให้จัดการภายใน | — |
| `label` `hint` `error` `required` `hideLabel` | เหมือน `Input` ทุกตัว (ใช้ shell เดียวกัน) | — |
| `placeholder` | ข้อความตอนยังไม่เลือก · **ใส่แล้วป้ายจะลอยทันที** | — |
| `size` | `sm` 36 · `md` 44 · `lg` 48 | `md` |
| `clearable` | ปุ่ม × ล้างค่ากลับเป็น `""` | `false` |
| `isLoading` | แทนช่องด้วยโครงร่าง | `false` |

**จงใจไม่มี** — ไอคอนฝั่งซ้าย ดู [ทำไมถึงไม่มี](#ไอคอนฝั่งซ้ายไม่มีและไม่ควรมี)

## ที่มาของทุกค่า

ทุกค่าลอกจาก `ActionSelect` ของ Portal ซึ่งเป็นช่องเลือกที่ใช้จริงวันนี้

| | ของจริงวันนี้ | DS | |
|---|---|---|---|
| ความสูง | `h-11` = 44 | `md` = 44 | ✅ ตรง |
| เส้นขอบ | `#0000003B` เขียนตายตัวในไฟล์ | `border-border-strong` = `#0000003b` | ✅ ค่าเดียวกัน แต่เป็น token |
| มุมโค้ง | `rounded-sm` | `rounded-sm` = 4px | ✅ ตรง |
| ป้าย | `shouldFloat={true}` — **ลอยตลอด** | ลอยเมื่อ focus / มีค่า / มี placeholder | ⚠️ ต่างกัน |
| สถานะโหลด | ไม่มีเลย | `isLoading` | 🆕 ของใหม่ |

### ป้ายลอยตลอด vs ลอยตามสถานะ

ของจริงลอยตลอด DS ลอยตามสถานะ — **ไม่ได้ทำให้ตรงกัน** เพราะ DS ใช้ shell ตัวเดียวกับ `Input`
ถ้าจะให้ Select ลอยตลอดต้องแยกพฤติกรรมออกจาก `Input` ซึ่งแลกไม่คุ้ม

ทางที่ใช้แทน: **ส่ง `placeholder` มา** แล้วป้ายจะลอยทันที (`floating` รวม `Boolean(placeholder)` อยู่แล้ว)
ซึ่งเป็นสิ่งที่ควรทำอยู่ดี — ช่องเลือกที่ไม่บอกว่าให้เลือกอะไรนั้นอ่านไม่ออก

## ไอคอนฝั่งซ้าย ไม่มีและไม่ควรมี

`Input` มี `prefixIcon` แต่ `Select` **ไม่มีโดยตั้งใจ**

`ActionSelect` ของจริงมี prop ชื่อ `icon` ซึ่ง**อ่านผิดได้ง่ายมาก** — มันไม่ใช่ไอคอนซ้าย แต่ถูกส่งต่อไปที่
`SelectTrigger` แล้ว**แทนที่ลูกศร**:

```tsx
{props.icon || <ChevronDown className="h-4 w-4 opacity-50" />}
```

และไล่ดูทั้ง repo แล้ว — **ไม่มีใครส่งเลยสักที่** ⇒ ไม่มีของจริงมารองรับ จึงไม่ใส่

📌 ลูกศรลงถือเป็นส่วนหนึ่งของตัว component ไม่ใช่ตัวเลือก — มันคือสิ่งที่บอกว่า
"นี่คือช่องเลือก ไม่ใช่ช่องพิมพ์" ปิดได้เมื่อไหร่ก็จะมีคนปิด

## 🔴 `isLoading` ไม่ใช่ `disabled`

| | ความหมาย | ผู้ใช้เห็นอะไร |
|---|---|---|
| `disabled` | เลือกไม่ได้ **ด้วยเหตุผลบางอย่าง** | ช่องจาง ๆ ที่ต้องเดาเองว่าทำไม |
| `isLoading` | ยังไม่รู้ว่ามีอะไรให้เลือก | โครงร่าง = "รอแป๊บ" |

dropdown ที่รอ API อยู่ต้องใช้ `isLoading` — ใช้ `disabled` แปลว่าไปโกหกผู้ใช้ว่าเลือกไม่ได้

**ไม่มีลูกศรตอนโหลด** โดยตั้งใจ — ลูกศรบอกว่ากดแล้วจะมีอะไรให้เลือก ซึ่งตอนนั้นยังไม่จริง

### ✅ แก้ชื่อที่ชนกันแล้ว (2026-08-08)

เดิม `ComboBox` · `MultiAutocomplete` · `EntityAutocomplete` ใช้ชื่อ `isLoading`
**คนละความหมาย** — ของพวกนั้นแปลว่า "ช่องยังอยู่ครบ แต่โชว์แถวกำลังโหลดในลิสต์"

ตอนนี้แยกเป็น 2 ชื่อทั่วทั้งระบบ:

| prop | ความหมาย | มีที่ไหน |
|---|---|---|
| `isLoading` | แทนทั้งช่องด้วยโครงร่าง | ทุก component |
| `optionsLoading` | ช่องอยู่ครบ · แถวกำลังโหลดในลิสต์ที่เปิดอยู่ | 3 ตัวที่มีลิสต์ให้ค้น |

⚠️ **breaking** สำหรับใครที่เคยส่ง `isLoading` เข้า 3 ตัวนั้น — แต่ตอนเปลี่ยนไล่แล้ว
**ไม่มีแอปไหนใช้ 3 ตัวนี้เลย** (ทุกแอปมี `ActionSelect*` ของตัวเอง) blast radius = DS เท่านั้น
และ TypeScript จับให้ ไม่ใช่พังเงียบ

## โครงร่างตอนโหลด

🔴 **ห้ามประกอบโครงร่างขึ้นใหม่เอง** ต้องผ่าน `FieldSkeleton` ซึ่งใช้ `FloatingFieldShell` ตัวเดียวกับของจริง

เหตุผล — ในของจริง **ป้ายเป็น `position:absolute`** จึงไม่กินความสูงเลย
ความสูงจริง = ช่อง + gap + บรรทัดข้อความข้างล่าง (จองที่ไว้เสมอ)

รุ่นก่อนของ `Input` ประกอบเองเป็น flow (แถบป้าย 14 + gap 6 + ช่อง 44 = 64) ซึ่ง**บังเอิญ**เท่าของจริง
(44 + 4 + 16 = 64) เฉพาะตอนมีป้าย — **วัดจริงในเบราว์เซอร์แล้วพอไม่มีป้ายเหลือ 44 เทียบกับของจริง 64 = กระโดด 20px**

ตอนนี้เท่ากันโดย**โครงสร้าง** ไม่ใช่โดยบังเอิญ

### ผลที่วัดได้จริง

story `Feedback/Skeleton states` → `Fields` · วัดความสูงกล่องนอกสุดในเบราว์เซอร์ สลับสถานะจริง

| เคส | โครงร่าง | ของจริง | |
|---|---|---|---|
| Input มีป้าย / ไม่มีป้าย / มีไอคอน | 64 | 64 | ✅ |
| Input sm · lg | 56 · 68 | 56 · 68 | ✅ |
| Select มีป้าย / ไม่มีป้าย / บังคับกรอก | 64 | 64 | ✅ |
| Textarea มีป้าย / ไม่มีป้าย | 108 | 108 | ✅ |
| Textarea lg | 124 | 124 | ✅ |
| ComboBox · MultiAutocomplete | 64 | 64 | ✅ |

**13/13 ไม่ขยับ**

## Figma ↔ code

| Figma | โค้ด |
|---|---|
| `State` = default · focus · error · disabled | สถานะภายใน + `error` + `disabled` |
| `Size` = sm · md · lg | `size` |
| `Content` = placeholder · filled | มีค่าหรือยัง |
| `Label` (text) | `label` |
| `Placeholder` (text) | `placeholder` |
| `Value` (text) | ป้ายของตัวเลือกที่เลือก |
| `Clearable` (bool) | `clearable` |
| `Loading` (bool) | `isLoading` |
| `<Option>` `State` = default · hover · selected · disabled | `SelectItem` + `data-[highlighted]` + `option.disabled` |
| `ตอนกางตัวเลือก` | `RadixSelect.Content` + `Viewport` |

**24 variant** (4 × 3 × 2) เท่ากับ `Input` เป๊ะ

### 🔴 ข้อบกพร่องที่เจอตอน sync — แก้แล้วทั้งสองฝั่ง

variant `Content=placeholder` ที่โคลนมาจาก `Input` **ไม่ผูกกับ component property ใดเลย** (`refs: {}`)
⇒ designer สลับเป็น placeholder แล้วพิมพ์ป้าย จะไม่มีอะไรเปลี่ยน แก้อะไรไม่ได้เลย

และ **ป้ายถูกซ่อน** ในสถานะนั้น ซึ่งขัดกับโค้ดเอง — `floating` รวม `Boolean(placeholder)` อยู่แล้ว
แปลว่ามี placeholder เมื่อไหร่ป้าย**ต้องลอย** ไม่ใช่หายไป

แก้แล้ว 2 อย่างในทั้ง `Select` และ `Input`: เพิ่ม property `Placeholder` แยกจาก `Label` · ให้ป้ายลอยในสถานะนั้น

## ค้าง

- ⚠️ `ActionSelectSearchable` ถูกใช้ **23 ครั้ง** เทียบกับ `ActionSelect` **10 ครั้ง** ⇒ ตัวที่คนใช้จริงมากกว่าคือ `ComboBox` ไม่ใช่ `Select`
- 🟡 **ยังมี `isLoading` ที่ผิดความหมายอีกตระกูล** — `ConfirmDialog` · `ConfirmCancelActions`
  ใช้แปลว่า "กดยืนยันแล้วกำลังทำงาน" ซึ่งตามกติกาของ DS เองต้องชื่อ `loading` (ยังไม่แก้ · ไม่ได้อยู่ในตระกูลฟอร์ม)
- `size` ยังชนกับ `Button` (`md` = 44 vs 36) — ข้อค้างร่วมของทั้งตระกูลฟอร์ม
- ยังไม่มี multi-select (`ActionSelectMulti` ของจริงมีอยู่)
- แผงตัวเลือกใน Figma เป็นเฟรมอ้างอิง ไม่ใช่ component ที่ประกอบอัตโนมัติ — designer ต้องวางเอง

## 🔴 ไม่มีตัวเลือกให้เลือก — และทางออก

```tsx
<Select
  options={[]}
  emptyText="ยังไม่มีนโยบายเวลาทำงาน"
  emptyAction={{ label: "ไปตั้งค่า", onClick: () => router.push("/work-time") }}
/>
```

**เดิม `options={[]}` ได้กล่องเปล่าไม่มีอะไรเลย** — ผู้ใช้กดแล้วแยกไม่ออกว่าโหลดไม่มา
ระบบพัง หรือไม่มีข้อมูลจริง ๆ · ของจริงเรียกสิ่งนี้ว่า `noOptionsText` อยู่แล้ว
**6 จุดบน Mediwork** และ `no_options` บน Portal — DS เป็นตัวเดียวที่ไม่มี

**🔴 dropdown ว่างที่ไม่มีทางออกคือทางตัน** — บันทึกไว้ตอน dev MediHR F3:
โรงพยาบาลที่ยังไม่เคยตั้งนโยบายเวลาทำงานเปิด dropdown แล้วเจอช่องว่าง แล้วไปต่อไม่ได้
ทั้งที่ทางแก้คือไปสร้างที่หน้าตั้งค่า

| prop | ค่า |
|---|---|
| `emptyText` | ข้อความ · ค่าเริ่มต้น `"No options"` (แอปส่งคำแปลมาเอง) |
| `emptyAction` | `{ label, onClick, icon? }` — ไม่ส่ง = มีแต่ข้อความ |
| `renderEmpty` | วาดเอง · ชนะสองตัวบน |

### สามอย่างที่ต้องจัดการเป็นพิเศษ เพราะปุ่มอยู่ใน listbox ของ Radix

1. **กดแล้วต้องปิด dropdown** — ปุ่มนี้มักพาไปหน้าอื่นหรือเปิด modal
   ถ้าไม่ปิด ลิสต์จะค้างทับสิ่งที่เพิ่งเปิด
   ⚠️ **เคยพลาดมาแล้ว**: คอมเมนต์เขียนว่าปิด แต่ `setOpen` ในไฟล์นี้คุมแค่ป้ายลอย
   ไม่ได้คุม Radix ⇒ ต้องส่ง `open` เข้า `RadixSelect.Root` ด้วย (วัดแล้วก่อนแก้
   `[role=listbox]` ยังอยู่หลังกด)
2. **ต้องรับ `Enter`/`Space` เอง** — ปุ่มธรรมดาในลิสต์ไม่อยู่ในลำดับ Tab และ Radix ดัก key อยู่
   คนที่ใช้คีย์บอร์ดล้วนคือกลุ่มเดียวกับที่ทางตันนี้ทำร้ายอยู่แล้ว
3. **`stopPropagation` ที่ `pointerup`** — ไม่งั้น Radix ตีความว่าเป็นการเลือกตัวเลือก

**พิสูจน์ในเบราว์เซอร์แล้ว**: กดปุ่ม → `onClick` ยิง → dropdown ปิด → เปิดใหม่เห็นตัวเลือกจริง
