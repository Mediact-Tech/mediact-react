# Checkbox · CheckboxGroup · RadioGroup · Switch

ตระกูลปุ่มติ๊ก — เอกสารเดียวกันเพราะ **แชร์ชิ้นส่วนตัวเดียวกัน**
(`ui/toggle-parts.tsx`) ถ้าแยกเอกสาร มันจะแยกค่ากันในไม่ช้า ซึ่งเกิดขึ้นมาแล้ว

| | |
|---|---|
| โค้ด | `packages/react/src/ui/Checkbox.tsx` · `CheckboxGroup.tsx` · `RadioGroup.tsx` · `Switch.tsx` · `toggle-parts.tsx` |
| Storybook | `UI/Checkbox` · `UI/RadioGroup` · `UI/Switch` |
| Figma | ไฟล์ **Mediact Design System** → หน้า `Toggles` → `Checkbox` (`122:63`) · `Radio` (`123:36`) · `Switch` (`127:97`) · `Switch labeled` (`131:116`) |
| สถานะ sync | ✅ ตรงกัน — 2026-08-09 |

---

## API

```tsx
<Checkbox label="ยอมรับเงื่อนไข" checked={v} onCheckedChange={setV} />
<Checkbox checked={all ? true : some ? "indeterminate" : false} />   // หัวตาราง
<CheckboxGroup label="ช่องทาง" value={v} onValueChange={setV} options={opts} />
<RadioGroup label="ประเภท" value={v} onValueChange={setV} options={opts} />
<Switch label="เปิดใช้งาน" checked={v} loading={saving} onCheckedChange={save} />
```

| prop | ค่า | ค่าเริ่มต้น | มีใน |
|---|---|---|---|
| `size` | `md` (20px) · `sm` (16px) | `md` | ติ๊ก + ตัวเลือกเดียว |
| `isLoading` | boolean — แทนที่ทั้งแถวด้วยโครงร่าง | `false` | ทั้งสี่ |
| `loading` | boolean — **กดแล้วกำลังบันทึก** | `false` | `Switch` เท่านั้น |
| `loadingLabel` | string — ข้อความให้โปรแกรมอ่านหน้าจอ | `"Saving"` | `Switch` |
| `label` · `description` | ReactNode | — | `Checkbox` · `Switch` |
| `error` | ReactNode — สลับเป็นสไตล์ error + `aria-invalid` | — | ทั้งสี่ |
| `checked` | `boolean \| "indeterminate"` | — | `Checkbox` |
| `options` | `{value,label,description?,disabled?}[]` | — | สองกลุ่ม |
| `orientation` | `vertical` · `horizontal` | `vertical` | สองกลุ่ม |
| `labelPosition` | `left` · `right` | `right` | `Switch` |
| `trackLabels` | `{ on, off }` — คำอยู่**ในราง** | — | `Switch` |

**จงใจไม่มี**

| ไม่มี | เหตุผล |
|---|---|
| prop `indeterminate` แยก | ทั้งสามแอปทำแบบนี้แล้ว **พัง** — ดูหัวข้อถัดไป |
| `variant` / `color` | ของจริงมี `variant="primary"` ตัวเดียวทุกแอป แกนที่มีค่าเดียวไม่ใช่แกน |
| `size="lg"` | ไม่มีจอไหนใช้ ช่องติ๊กใหญ่กว่า 20px กินพื้นที่โดยไม่ได้อ่านง่ายขึ้น |
| ป้ายกำกับฝั่งซ้ายของ checkbox | ไลบรารีเดิมมี 4 ทิศ ของจริงใช้ `end` อย่างเดียวทั้ง 4 แอป |
| `size` ของ `Switch` | ไม่มีจอไหนใช้สวิตช์ขนาดอื่น — 44×24 ตรงกันทั้ง Portal และ MediHR |
| ทรงของ Medimatch `VisibilityToggle` (62×22 + ไอคอน) | คนละทรงกับ `trackLabels` — รอเคสที่สองก่อนค่อยรวม |
| `Switch` แบบสองป้าย (segmented) | นั่นคือ `PillSwitch` ไม่ใช่สวิตช์ — ดูหัวข้อ "ชื่อชนกัน" |

## 🔴 `indeterminate` — ข้อผิดพลาดที่อยู่บน production ทั้งสามแอป

`ActionTabel` ของ Portal · MediHR · Medimatch เขียนหัวตารางแบบนี้:

```tsx
<ActionCheckbox
  checked={table.getIsAllPageRowsSelected()}      // false เมื่อเลือกบางแถว
  indeterminate={table.getIsSomePageRowsSelected()}  // prop ของตัวเอง
/>
```

พิสูจน์ด้วยการ render จริง (ไม่ใช่การอ่านโค้ดเดา):

| กรณี | `data-state` | `aria-checked` | เห็นสัญลักษณ์ไหม |
|---|---|---|---|
| แบบที่แอปใช้ | `unchecked` | `false` | **ไม่มี indicator เลย** |
| `checked="indeterminate"` | `indeterminate` | `mixed` | มี |

เพราะ `RadixCheckbox.Indicator` จะ render **ก็ต่อเมื่อ** state เป็น `checked`
หรือ `indeterminate` เท่านั้น ⇒ ตอนเลือกไปครึ่งหน้า ช่องหัวตาราง**ว่างเปล่า**
และโปรแกรมอ่านหน้าจอบอกว่า "ยังไม่ได้เลือก"

`DataTable` ของ DS ทำถูกอยู่แล้ว (`data/DataTable.tsx:343`) — ที่พังคือ `ActionTabel`
ของแต่ละแอป

## 🔴 `Switch` — ชื่อเดียวกัน คนละ component

สำรวจแล้วเจอ **6 แบบที่ต่างกัน** ใน 4 แอป:

| # | ที่อยู่ | หน้าตา |
|---|---|---|
| 1 | Portal · MediHR `ui/Switch` (ไฟล์เดียวกันทุกไบต์) | ราง 44×24 เขียวอ่อน `#85E0BA` · **ปุ่มเปลี่ยนเป็นเขียวเข้ม** `#0CB679` |
| 2 | Portal `ProductAccessToggle` | ตัวเดิม ทับสีรายผลิตภัณฑ์ (เขียว/น้ำเงิน) ที่ 40–50% |
| 3 | Medimatch `ui/Switch` | **ไม่ใช่สวิตช์** — segmented pill สองป้าย (= `PillSwitch` ของ DS) |
| 4 | Medimatch `VisibilityToggle` | 62×22 · ราง `#B3E9D0` · ปุ่ม `#0BB767`/`#8995A1` + ไอคอน |
| 5 | MediHR `SubUnitActiveToggle` | 24px มี ON/OFF **ขนาด 8px** ในราง · โทเคน `--color-switch-on: #10b981` |
| 6 | Mediwork MUI `<Switch>` | `color="primary"` 13 จอ · อีก 1 จอ hardcode `#1565C0` |

**ใครย้ายมาใช้ DS ต้องดูก่อนว่าจอนั้นใช้ตัวไหน** — ของ Medimatch (#3) ต้องไป
`PillSwitch` ไม่ใช่ `Switch` ชื่อมันชนกันเฉย ๆ

### "เปิด" เป็นสีเขียว ไม่ใช่สีแบรนด์

5 ใน 6 แบบใช้เขียว: `#0CB679` · `#0BB767` · `#10b981` · success-green —
MediHR ถึงขั้นตั้งโทเคนชื่อ `--color-switch-on` มีแต่ Mediwork MUI ที่ใช้ primary
และไฟล์เดียวในนั้นยัง override เป็นน้ำเงิน

เหตุผลเชิงความหมายก็ตรงกัน: **เปิด/ปิดคือสถานะ ไม่ใช่แบรนด์** — เหตุผลเดียวกับที่
ตัวเลขในตารางไม่เปลี่ยนสีตามแอป วัดแล้วเขียวเท่ากันทั้งสี่ธีม `rgb(11,183,103)`

### ปุ่มเลื่อนขาวเสมอ

ของจริง Portal/MediHR เปลี่ยนปุ่มเป็น `#0CB679` บนรางเขียวอ่อน `#85E0BA` —
วัดคอนทราสต์ปุ่มต่อราง ได้ **1.68:1** คือปุ่มแทบละลายหายไปในรางตอนเปิด
ซึ่งตรงข้ามกับหน้าที่ของมัน ปุ่มขาวบน `#0bb767` ได้ 2.63:1 + มีเงาอีกชั้น

## 🔴 `loading` ≠ `disabled` — 14 จอทำผิดอยู่

Mediwork 13 จอในหน้าตั้งค่ากฎเขียนแบบนี้:

```tsx
<Switch checked={isEnabled} onClick={onToggle} disabled={isToggleLoading} />
```

และ MediHR `SubUnitActiveToggle` มี `pending?: boolean` ที่ทำแค่ `disabled={pending}`

⇒ ตอนกำลังบันทึก สวิตช์**จางลงเฉย ๆ** แยกไม่ออกจาก "คุณไม่มีสิทธิ์แตะอันนี้"
ทั้งที่สวิตช์เป็นตัวควบคุมที่ **มีผลทันทีโดยไม่มีปุ่มบันทึก** — สถานะกำลังส่งจึงจำเป็น

วัดจาก Storybook:

| | ทึบแสง | เคอร์เซอร์ | `aria-busy` | ตัวหมุน |
|---|---|---|---|---|
| ปกติ | 1 | pointer | — | — |
| `loading` | **1** | `progress` | `true` | ✅ |
| `disabled` | **0.5** | `not-allowed` | — | — |

และ `loading` **คงสถานะเดิมไว้** จนกว่าจะได้คำตอบ — ถ้าพลิกทันทีแล้ว API พัง
ผู้ใช้จะเห็นสวิตช์เด้งกลับเอง

⚠️ ต้องเขียนเป็น `disabled:cursor-progress` ไม่ใช่ `cursor-progress` เปล่า ๆ —
ตอน `loading` ปุ่มถูก `disabled` จริง กฎ `disabled:cursor-not-allowed` ในรูปทรงหลัก
จึงชนะ (วัดเจอ: เคอร์เซอร์ออกมาเป็น not-allowed ทั้งที่กำลังบันทึกอยู่)

## `trackLabels` — คำอยู่ในราง (การ์ดหน่วยงาน)

ต้นแบบคือ `SubUnitActiveToggle` ของ MediHR ที่ใช้ในการ์ดหน่วยงาน ซึ่งไม่มีที่ให้เขียน
ป้ายกำกับข้างนอก จึงเอาคำว่า "เปิดใช้งาน/ปิดใช้งาน" ไปไว้ในรางเลย

```tsx
<Switch
  aria-label={`สถานะของ ${subUnit.name}`}
  checked={subUnit.isActive}
  loading={pendingId === subUnit.id}
  onCheckedChange={toggle}
  trackLabels={{ on: t("sub_unit.toggle_on"), off: t("sub_unit.toggle_off") }}
/>
```

📐 วัดจาก MediHR: สูง 24 · pad 2 · gap 4 · ปุ่ม 20 · **เปิด = ปุ่มอยู่ขวา**
(คอมเมนต์ในไฟล์ต้นทางเขียนว่า *"Active = thumb on the left"* — วัดแล้วผิด)

### สองอย่างที่แก้จากของเดิม

| | MediHR วันนี้ | ที่นี่ | ทำไม |
|---|---|---|---|
| ตัวอักษร | **8px** | 12px (`text-caption`) | 8px อ่านไม่ออก ภาษาไทยมีวรรณยุกต์ยิ่งหนัก |
| ความกว้างราง | `Active` **57.94** → `Inactive` **65.38** | **88.70 → 88.70** | สลับทีเดียวรางกระตุก 7.4px ทั้งแถวในการ์ดเลื่อนตาม |

ความกว้างคงที่ได้เพราะวางสองคำ **ซ้อนกันในช่อง grid เดียว** แล้วซ่อนอันที่ไม่ใช้ด้วย
`invisible` ⇒ ความกว้าง = คำที่ยาวกว่าเสมอ **โดยโครงสร้าง** ไม่ใช่ไปตั้ง `w-` ตายตัว
(เทคนิคเดียวกับที่ `SkeletonBox` ใช้ให้โครงร่างกว้างเท่าของจริง)

### คอนทราสต์ผ่านทั้งสองสถานะ

| สถานะ | ราง | ข้อความ | ได้ |
|---|---|---|---|
| เปิด | `rgb(11,183,103)` | `text/black` `rgb(25,25,25)` | **6.68** ✅ |
| ปิด | `rgb(229,231,235)` | `text/body` `rgb(83,90,97)` | **5.65** ✅ |

🔴 ข้อความในรางเป็นสีเข้ม **ไม่ใช่สีขาวแบบของเดิม** — ขาวบน `#0bb767` ได้ 2.63:1
ซึ่งตกเกณฑ์ 4.5:1 ของข้อความปกติ ของเดิม MediHR ใช้ขาวบน `#10b981` = 2.56:1 ก็ตกเช่นกัน

⚠️ คำในรางเป็น `aria-hidden` — สถานะจริงประกาศผ่าน `role="switch"` + `aria-checked`
ถ้าปล่อยให้อ่าน โปรแกรมอ่านหน้าจอจะพูดทั้งสองคำติดกัน **ถ้าไม่มี `label` ข้างนอก
ต้องส่ง `aria-label` มาเสมอ**

## รูปทรง — ที่มาของทุกค่า

สำรวจก่อนแก้: `<Checkbox` 26 จุด · `<Radio` 33 จุด · `<Switch` 31 จุด ใน 4 แอป

| | Portal | MediHR | Medimatch | Mediwork |
|---|---|---|---|---|
| ที่มา | `ui/Checkbox.tsx` | **ไฟล์เดียวกับ Portal ทุกไบต์** | ไฟล์ของตัวเอง | MUI |
| กล่องติ๊ก | 16×16 | 16×16 | 16×16 · ขอบ **2px** | 20/24 |
| radio | 20×20 | 20×20 | 20×20 | 20/24 |
| มุม | 2px | 2px | 2px | — |
| สีตอนติ๊ก | `#05A5D8` ฝังตาย | `#05A5D8` | `#0b77c6` | `theme.primary` |
| วงแหวนโฟกัส | `cherry-red-600/50` | เดียวกัน | เดียวกัน | — |
| ป้ายกำกับ | 14px/500 `#535A61` | เดียวกัน | เดียวกัน | — |

ค่าทั้งหมดข้างบน **วัดจากเบราว์เซอร์** โดยฉีด element ที่ใส่คลาสชุดเดียวกับ
component ของแอปลงในหน้าที่ล็อกอินแล้วของแอปนั้น แล้วอ่าน computed style
(ทำได้เพราะคลาสในไฟล์เหล่านั้นเป็น string คงที่ ไม่ได้ผ่าน theme/`sx`)

ค่าที่ DS ใช้:

| | ค่า | มาจาก |
|---|---|---|
| กล่อง `md` | 20px | radio ของทั้งสามแอปเป็น 20px ตรงกัน — บังคับให้ checkbox เท่ากัน |
| กล่อง `sm` | 16px | ขนาดเดิมของ checkbox ทั้งสามแอป เก็บไว้ให้แถวตารางที่แน่น |
| มุม | 2px `rounded-xs` | วัดจาก Portal ได้ `border-radius: 2px` เป๊ะ (Tailwind `rounded-xs` = 2px) |
| ขอบ | 1px `border/input` | token เดียวกับ `Input` — ช่องติ๊กกับช่องกรอกอยู่ในฟอร์มเดียวกัน |
| สีตอนติ๊ก | `brand/default` | ของจริงฝังตายทั้งสามแอปและ**ไม่ตรงกับแบรนด์ตัวเองสักแอป** |
| สัญลักษณ์ | 14px / 12px · เส้นหนา 3 | ของจริงใช้ `size-[70%]` + `strokeWidth={3}` ตรงกันทั้งสามแอปโดยไม่ได้นัดกัน |
| จุด radio | 10px / 8px | 50% ของกล่อง — Medimatch ใช้ 11px บนกล่อง 20 |
| ราง switch | 44×24 · ขอบโปร่ง 2px | วัดจาก Portal (= MediHR ไฟล์เดียวกัน) |
| ปุ่มเลื่อน | 20px · เลื่อน 20px | 44 − 2×2 − 20 = 20 พอดี — วัดได้ 0 / 20 ทั้งในเบราว์เซอร์และ Figma |
| ราง switch ตอนปิด | `#e5e7eb` | วัดได้เป๊ะ (`gray-200` ในโค้ด · `Primitives/neutral/100` ใน Figma) |
| ราง switch ตอนเปิด | `success-green-primary` `#0bb767` | = `--mx-green-500` = Figma `success/default` ทั้งสี่โหมด |
| ป้ายกำกับ | `text/body` | `--color-text-body` = `#535a61` **ตรงกับที่วัดได้เป๊ะ** |
| วงแหวนโฟกัส | `brand/40` + offset 2 | ของจริงเป็นสีแดง ซึ่งเป็นสีของ error |

⚠️ รางตอนปิดยัง **ไม่มีชื่อ semantic** — โค้ดเรียก `gray-200` ส่วน Figma ผูกกับ
primitive `neutral/100` ค่าเดียวกัน (`#e5e7eb`) เป็นช่องว่างที่การย้าย token ต้องปิด
ไม่ได้ตั้งชื่อใหม่ตอนนี้เพราะมีที่ใช้ที่เดียว

### จัดแนวกล่องกับบรรทัดแรก — วัดแล้ว ไม่ได้กะ

กล่องอยู่ในที่ครอบสูง 20px เสมอ แล้วจัดกึ่งกลาง ⇒ ขนาดไหนก็ตรงบรรทัดโดยโครงสร้าง

| | ขอบบนกล่อง | ขอบบนบรรทัด | กึ่งกลางกล่อง | กึ่งกลางบรรทัด |
|---|---|---|---|---|
| `md` | 16 | 16 | 26 | 26 |
| `sm` | 72 | 70 | **80** | **80** |

บรรทัดแรกใช้ `leading-5` (20px) จงใจ ไม่ใช่ `leading-tight` (= 17.5px) —
17.5 ไม่เท่ากับกล่อง 20px แล้วต้องมาไล่ปรับ margin ทีหลังทุกครั้งที่เปลี่ยนขนาด

## สถานะโหลด

`isLoading` ครอบ **ทั้งแถว** ไม่ใช่แค่กล่อง — เนื้อหาจริงยังอยู่ใน DOM แบบ
`invisible` ⇒ ความกว้างเท่าของจริงโดยไม่ต้องเดา

| | ปกติ | ตอนโหลด |
|---|---|---|
| `Checkbox` แถวมีป้ายกำกับ + คำอธิบาย | 1248 × 38 | **1248 × 38** |
| `Checkbox` กล่องเปล่า | 20 × 20 | **20 × 20** |
| `Switch` แถวมีป้ายกำกับ + คำอธิบาย | 868 × 38 | **868 × 38** |
| `Switch` รางเปล่า | 44 × 24 | **44 × 24** |
| `Switch` แบบมีคำในราง | 88.70 × 24 | **88.70 × 24** |

`RadioGroup` / `CheckboxGroup` วาดโครงร่างเท่า `options.length` ถ้ารู้ตัวเลือก
ล่วงหน้า ถ้าไม่รู้ใช้ 3 แถว

## 🔴 คอนทราสต์ — ยังไม่แก้ ต้องให้ทีมออกแบบเคาะ

เครื่องหมายถูกใช้ `brand/foreground` (= ขาว) บนพื้น `brand/default` วัดครบสี่ธีม:

| ธีม | พื้น | คอนทราสต์ | เกณฑ์กราฟิก 3:1 |
|---|---|---|---|

## Figma ↔ โค้ด

| Figma | โค้ด |
|---|---|
| `State` = Unchecked / Checked / Indeterminate | `checked` = `false` / `true` / `"indeterminate"` |
| `State` = Unchecked / Checked (Radio) | `value` ตรง/ไม่ตรงกับ `RadioGroupItem` |
| `State` = Off / On (Switch) | `checked` |
| `Switch labeled` `State` Off/On + text `On text`/`Off text` | `trackLabels={{ on, off }}` |
| `Size` = Medium / Small | `size` = `md` / `sm` |
| boolean `Loading` (Switch) | `loading` |
| boolean `Text` | มี `label` หรือไม่ |
| boolean `Description` | มี `description` หรือไม่ |
| boolean `Disabled` | `disabled` |
| text `Label text` / `Description text` | `label` / `description` |
| — | `isLoading` · `error` — **ไม่มีใน Figma** (มีเฟรมอ้างอิง `ตอนโหลด` แทน) |
| — | `orientation` · `labelPosition` — เป็นเรื่องของ layout ไม่ใช่ของตัวควบคุม |

เฟรมอ้างอิงบนหน้าเดียวกัน: `เลือกทั้งหน้า — ตอนเลือกบางแถว` · `กลุ่มช่องติ๊ก` ·
`กลุ่มปุ่มตัวเลือก` · `ตอนโหลด` · `❌ ของจริงทำอยู่แบบนี้ — อย่าลอกกลับเข้ามา` ·
`แถวตั้งค่า — ข้อความซ้าย สวิตช์ขวา` · `กำลังบันทึก ≠ ปิดใช้งาน` ·
`การ์ดหน่วยงาน — สวิตช์มีข้อความในราง`

⚠️ **`Switch labeled` ใน Figma กว้างไม่เท่ากันสองสถานะ** (On 88 · Off 85) เพราะ Figma
แสดงทีละคำ ส่วนโค้ดล็อกไว้ที่คำที่ยาวกว่า — ความกว้างคงที่เป็นพฤติกรรมตอนรัน
ที่ component ของ Figma แสดงไม่ได้ อย่าออกแบบตามความกว้างที่เห็น

⚠️ ไม่มี Code Connect (ต้อง Figma Organization plan) — ตารางนี้คือตัวยึดแทน

## ค้าง

- [ ] **คอนทราสต์ `brand/foreground` บน Mediwork/Medimatch** — วัดแล้ว รอทีมออกแบบเลือกทาง (ข้างบน)
- [ ] **รางของ `Switch` มองแทบไม่เห็นบนพื้นขาว** — วัดได้ ตอนเปิด **2.63:1** ตอนปิด **1.24:1** ต่ำกว่าเกณฑ์กราฟิก 3:1 ทั้งคู่ ของจริงทุกแอปจางกว่านี้อีก ทางแก้คือใส่เส้นขอบให้ราง ซึ่งเปลี่ยนหน้าตาทุกแอป — ยังไม่ทำ
- [ ] `Switch` ไม่มี `size` ทั้งที่ตัวอื่นในตระกูลมี (ดู decision log)
- [ ] ยังไม่มี "การ์ดที่ทั้งใบเป็นตัวเลือก" (`ActionRadioItem` ของ Medimatch) — เป็นรูปแบบจริงที่ใช้อยู่ แต่รอเคสที่สองก่อนค่อยยกขึ้นมา
- [ ] Medimatch `VisibilityToggle` (62×22 + ไอคอนในราง) ยังไม่รองรับ — คนละทรงกับ `trackLabels` รอเคสที่สอง
- [ ] `error` ของ `Checkbox` ทำให้ขอบแดง `Switch` ใส่วงแหวนแดง แต่ `RadioGroup` / `CheckboxGroup` แดงแค่ข้อความใต้กลุ่ม ตัวควบคุมไม่เปลี่ยน
- [ ] แอปทั้งสี่ยังไม่ได้ย้ายมาใช้ — `ActionCheckbox` / `RadioItem` / `ActionSwitch` ของแต่ละแอปยังอยู่ครบ
- [ ] Medimatch `ui/Switch` ต้องย้ายไป `PillSwitch` ไม่ใช่ `Switch` — ต้องบอกก่อนใครเริ่มย้าย
