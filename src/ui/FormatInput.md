# FormatInput

ช่องกรอกที่จัดรูปแบบระหว่างพิมพ์ — เลขบัตรประชาชน เบอร์โทร จำนวนเงิน หรือรูปแบบที่เขียนเอง

| | |
|---|---|
| โค้ด | `packages/react/src/ui/FormatInput.tsx` |
| Storybook | `UI/FormatInput` |
| Figma | **ไม่มี component แยก** — มีแผ่นอ้างอิงในหน้า `Input` → `รูปแบบที่มีให้ใช้` (`51:2`) |
| สถานะ sync | ✅ ไม่ต้อง sync — ไม่มีอะไรต่างทางสายตา (2026-08-08) |

---

## API

```tsx
<FormatInput
  label="เลขบัตรประชาชน"
  format="thaiId"
  value={raw}
  onValueChange={setRaw}   // คืน "1234567890123" ไม่ใช่ "1-2345-67890-12-3"
/>
```

| prop | ค่า | ค่าเริ่มต้น |
|---|---|---|
| `format` | ชื่อ preset · สตริง mask · หรือ `{ format, removeFormatting }` | **บังคับ** |
| `value` | ค่าดิบ | — |
| `onValueChange` | `(raw: string) => void` — **คืนค่าดิบเสมอ** | — |
| `showMask` | โชว์ `_` ในช่องที่ยังไม่กรอก (เฉพาะ mask) | `false` |
| `thousandSeparator` / `decimalScale` / `allowNegative` | เฉพาะรูปแบบตัวเลข | `,` / `2` / `false` |
| prop ของ `Input` ทั้งหมด | `label` `prefixIcon` `error` `size` `isLoading` … | — |

**จงใจไม่มี** — `onChange` ที่คืนค่าที่จัดรูปแบบแล้ว (สิ่งที่ส่งขึ้นหลังบ้านต้องเป็นค่าดิบเสมอ · การมีสองทางออกแปลว่าจะมีคนส่งผิด)

## รูปแบบสำเร็จรูป

| ชื่อ | ผล | ที่มา |
|---|---|---|
| `thaiId` | `1-2345-67890-12-3` (13 หลัก) | MediHR เก็บ `idCardNumber` แต่**วันนี้ไม่มีการจัดรูปแบบเลย** — validate แค่ `min(1).max(20)` |
| `phone` | `081-234-5678` (10 หลัก) | เบอร์มือถือไทย |
| `bankAccount` | `123-4-56789-0` (10 หลัก) | รูปแบบเลขบัญชีธนาคารไทย |
| `currency` | `1,234,567.89` | **ค่าเดียวกับที่ Medimatch ใช้อยู่กับช่องค่าจ้าง** (`thousandSeparator=","` `decimalScale={2}` `allowNegative={false}`) |

เพิ่ม preset ได้ **แต่ต้องมีของจริงมารองรับก่อน** — ไม่ใส่เผื่อ

## รูปแบบที่ส่งเข้ามาเอง

**สตริง mask** — `#` คือช่องตัวเลข 1 หลัก

```tsx
<FormatInput format="##-###-######" />
```

**ฟังก์ชัน** — ต้องให้ทั้งขาจัดและขาถอด ไม่งั้นค่าที่คืนจะเป็นค่าที่จัดแล้ว

```tsx
<FormatInput
  format={{
    format: (raw) => /* ค่าดิบ → สิ่งที่แสดง */,
    removeFormatting: (v) => /* สิ่งที่แสดง → ค่าดิบ */,
  }}
/>
```

ใช้เมื่อ mask ตำแหน่งคงที่ทำไม่ได้ — เช่นทะเบียนรถที่มีทั้งตัวอักษรและตัวเลขปนกัน

---

## 🔴 ไม่ได้เขียนตัวจัดรูปแบบเอง

ใช้ **`react-number-format`** ซึ่ง **อยู่ในสแตกอยู่แล้ว** — Medimatch และ Mediwork ใช้กับช่องค่าจ้าง 3 จุด (`ActionInputWage`)

เหตุผลที่ไม่เขียนเอง: **การคืนตำแหน่งเคอร์เซอร์หลังแทรกอักขระคั่นกลางสตริง** เป็นจุดที่ input แบบ mask พังบ่อยที่สุด และ lib นี้แก้ไว้แล้ว

| ต้องการ | ใช้ตัวไหนของ lib |
|---|---|
| จำนวนเงิน | `NumericFormat` |
| mask ตำแหน่งคงที่ | `PatternFormat` |
| ฟังก์ชันเอง | `NumberFormatBase` |

ราคาที่จ่าย: `@mediact/react` มี dependency เพิ่ม 1 ตัว (~228KB บนดิสก์) — ทุกแอปที่ import DS จะได้ไปด้วย

## ผลที่วัดได้จริง

พิมพ์ลงไปในเบราว์เซอร์แล้วอ่านทั้งสิ่งที่เห็นและค่าดิบ:

| รูปแบบ | พิมพ์ | เห็นบนจอ | ค่าดิบที่คืน |
|---|---|---|---|
| `thaiId` | `12345678901234` (เกิน 1 หลัก) | `1-2345-67890-12-3` | `1234567890123` ✂️ ตัดเอง |
| `phone` | `0812345678` | `081-234-5678` | `0812345678` |
| `bankAccount` | `1234567890` | `123-4-56789-0` | `1234567890` |
| `currency` | `1234567.891` | `1,234,567.89` | `1234567.89` ✂️ |
| mask เอง | `12345678901` | `12-345-678901` | `12345678901` |
| ฟังก์ชันเอง | `กข1234` | `กข 1234` | `กข1234` |

**เคสแทรกกลางสตริง** — พิมพ์ 13 หลักครบ แล้วเลื่อนเคอร์เซอร์ไปตำแหน่งที่ 2 พิมพ์ `9`:
`1-9234-56789-01-2` · ค่าดิบ `1923456789012` · **เคอร์เซอร์อยู่ที่ 3** ✓ ไม่กระเด็นไปท้าย

## Figma

**ไม่มี component แยก** — `FormatInput` ใช้ `Input` เป็นฐานทั้งหมด (`customInput={Input}`) จึงได้ป้ายลอย ไอคอน สถานะ ขนาด และโครงร่างตอนโหลดเหมือนกันเป๊ะ สิ่งที่ต่างคือ**สิ่งที่พิมพ์ลงไปแล้วเห็นอะไร** ซึ่งเป็นพฤติกรรม ไม่ใช่รูปทรง

สร้างแยกจะได้ component ที่หน้าตาซ้ำกับ `Input` 100% แล้วต้องแก้สองที่ทุกครั้ง

**แต่มี "แผ่นอ้างอิง" แทน** — หน้า `Input` → เฟรม `รูปแบบที่มีให้ใช้` (`51:2`)

เพราะช่องว่างจริงไม่ใช่รูปทรง แต่คือ **designer ไม่มีทางรู้ว่ารูปแบบไหนมีอยู่จริงในระบบ** ถ้าไปวาด `x-xxxx-xxxxx-xx-x` เอาเอง dev จะได้โจทย์ที่ไม่ตรงกับ preset ที่มี

แผ่นนั้นคือ instance ของ `Input` จริง 4 อัน ใส่ค่าตัวอย่างที่**วัดได้จากการพิมพ์จริง** พร้อมชื่อ preset ที่ต้องเขียนกำกับ (`format="thaiId"`) และหมายเหตุข้อจำกัด (เช่นเบอร์บ้านยังไม่รองรับ)

📌 กติกาที่เขียนไว้บนแผ่น: **ต้องการรูปแบบที่ไม่มีในนี้ = งานใหม่ ต้องคุยก่อน ไม่ใช่วาดเอง**

## ค้าง

- `phone` รองรับเฉพาะมือถือ 10 หลัก — **เบอร์บ้าน 9 หลักยังใช้ไม่ได้** (`PatternFormat` ต้องความยาวคงที่) ถ้าต้องรองรับต้องเขียนเป็นฟังก์ชันเอง
- ยังไม่มี `taxId` (13 หลักเหมือน `thaiId` แต่คนละบริบท) — ยังไม่เจอของจริง
- ยังไม่ได้เอาไปแทน `ActionInputWage` ของ Medimatch (3 จุด) ที่ทำเรื่องเดียวกันอยู่
- MediHR ยังไม่จัดรูปแบบ `idCardNumber` เลย — เป็นจุดที่เอาไปใช้ได้ทันที
