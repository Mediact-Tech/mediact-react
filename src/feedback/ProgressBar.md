## ที่มาของตัวเลข

**วัดจาก Medimatch ที่รันจริง 2026-09-11** ทั้งสองจุดที่มีแถบอยู่แล้ว
(`create-job/PackageCardCredit` เขียนด้วย Tailwind · `list-my-package/PackageCard` ใช้ MUI
`LinearProgress`) — ป้อนข้อมูลชุดเดียวกันแล้ววัด computed style:

| | Tailwind (A) | MUI (B) |
|---|---|---|
| ความสูง | 7.99px | 7.99px |
| ราง | `rgb(239,239,239)` | `rgb(239,239,239)` |
| แถบ | `rgb(6,181,237)` | `rgb(6,181,237)` |
| ทรง | pill | pill |

🔑 **สองจุดนี้ "drift" กันแค่วิธีเขียน ไม่ใช่ผลลัพธ์** — A ใช้ token ส่วน B ฝัง hex ใน `sx`
แต่ค่าออกมาเท่ากันทุกช่อง ⇒ spec ของ component นี้จึงไม่มีอะไรต้องให้ design ตัดสิน
(ต่างจาก *กรอบการ์ด* ที่ล้อมมันอยู่ ซึ่ง drift จริงและต้องเคาะแยก)

B เขียน `borderRadius: 4` ใน `sx` ซึ่ง MUI คูณด้วย `theme.shape.borderRadius` เป็น **16px**
แต่บนแถบสูง 8px ทั้ง 16px และ `rounded-full` ถูกหนีบเหลือ 4px เท่ากัน ⇒ เห็นเป็น pill ทั้งคู่

## Token

```css
--color-progress-track: var(--mx-neutral-50);      /* ราง */
--color-progress-fill:  var(--color-info-default); /* แถบ */
```

🔴 **แยกเป็นชื่อของตัวเองแทนที่จะให้ component เรียก `info-*` ตรง ๆ** เพราะแถบนี้บอก
*สัดส่วนโควตา* ไม่ใช่ *ข้อความเชิงข้อมูล* ⇒ ธีมต้องเปลี่ยนสีแถบได้โดยไม่ลากสี
"ข้อความแจ้งข้อมูล" ทั้งระบบไปด้วย

**ผลกับ Medimatch: ได้สีเดิมเป๊ะโดยไม่ต้องประกาศ token เพิ่มสักตัว**
- ราง — Medimatch ประกาศ `--color-progress-track: #efefef` ของตัวเองอยู่แล้วและประกาศ
  ทีหลัง DS ⇒ ชนะค่าตั้งต้น
- แถบ — ตกมาที่ `info-default` ซึ่งที่ Medimatch = `#06b5ed` พอดี

⚠️ **ค่าตั้งต้นของราง (`neutral-50` = `#f3f4f6`) ไม่เท่ากับ `#efefef` ของ Medimatch**
แอปอื่นที่ไม่ override จะได้ `#f3f4f6` ซึ่งเป็นเทาของ DS — ตั้งใจ ไม่ใช่พลาด

## โทน

`info` (ค่าตั้งต้น) · `success` · `warning` · `danger`

⚠️ **วันนี้ยังไม่มี call site ไหนใช้ 3 โทนหลัง** — ใส่มาเพราะแถบโควตาเปลี่ยนความหมาย
ตามระดับเป็นเรื่องปกติ (ใกล้เต็ม = เตือน · เต็ม = อันตราย) และ Medimatch มีจอ
"เครดิตหมด" อยู่จริงแล้ว (`CreditLimitReachedBanner`) ⇒ ถ้าไม่ให้มาแต่แรก จุดแรกที่
ต้องการจะ fork ด้วย `className` แล้วโทนจะกระจายกันเองทีละจอ
**ถ้าผ่านไปหลายเดือนแล้วยังไม่มีใครใช้ ให้ถอดออก** อย่าปล่อยให้เป็นตัวเลือกที่ตายแล้ว

## ทำไมไม่ใช่ `<progress>`

UA stylesheet ของแต่ละเบราว์เซอร์วาด `<progress>` คนละแบบ และจะรื้อได้ต้องใช้
`::-webkit-progress-bar` / `::-moz-progress-bar` ซึ่งเขียนเป็น utility ไม่ได้
⇒ component จะขึ้นกับ reset ของแอปปลายทาง ซึ่ง §9 ของ CLAUDE.md ห้ามไว้ตรง ๆ
(**Mediwork ถอด preflight ทิ้งโดยตั้งใจ** เพื่อไม่ให้ชนกับ MUI)

สอง `<div>` + `role="progressbar"` ให้ผลเท่ากันทุกเบราว์เซอร์และคุมได้เต็ม
มีเทสตรึงไว้ว่าห้ามมี `<progress>` ใน output

## กับดักที่เจอมาแล้ว

- 🔴 **`width: NaN%` ไม่ได้แปลว่า 0 — แปลว่าเบราว์เซอร์ทิ้งทั้งกฎ** แล้วแถบกว้างเต็มราง
  ซึ่งอ่านว่า "ใช้หมดแล้ว" ทั้งที่ยังไม่มีโควตาด้วยซ้ำ · `creditsUsed / creditsTotal`
  ให้ `NaN` ทันทีที่ `creditsTotal = 0` ⇒ หนีบทุกค่าก่อนใช้เสมอ (มีเทส)
- 🔴 **ค่าเกิน 100 เกิดขึ้นจริง** เมื่อใช้เกินโควตา — ไม่หนีบแล้วแถบจะยื่นออกนอกราง
- **แถบเปล่าไม่มีข้อความในตัว** ⇒ ถ้าไม่ส่ง `label` โปรแกรมอ่านหน้าจอจะได้แค่
  "progress bar 40%" โดยไม่รู้ว่าโควตาอะไร · จอที่มีป้ายอยู่แล้วส่ง `aria-labelledby` แทนได้
- **`isLoading` ต้องเป็นโครงร่างที่สูงเท่าราง ไม่ใช่แถบ 0%** — แถบ 0% อ่านว่า
  "ยังไม่ใช้เลย" ซึ่งเป็นข้อมูลที่เรายังไม่รู้

| วันที่ | เรื่อง | ทำไม | ราคาที่ยอมจ่าย |
|---|---|---|---|
| 2026-09-11 | สร้าง `ProgressBar` ใน DS แทนที่จะให้แอปใช้ MUI ต่อ | `LinearProgress` เป็นสิ่งเดียวที่ยังตรึง `@mui/material` ไว้ใน Medimatch (4 ไฟล์) — ถอดได้แปลว่าถอด dependency ทั้งตัว | DS รับภาระ component เพิ่มอีกตัวที่ยังมีผู้ใช้แอปเดียว |
| 2026-09-11 | token แยก `progress-*` ไม่เรียก `info-*` ตรง ๆ | แถบบอกสัดส่วน ไม่ใช่ข้อความแจ้งข้อมูล — ธีมต้องเปลี่ยนสีแถบได้โดยไม่ลากสี info ทั้งระบบ | เพิ่ม token 2 ตัวในชั้น semantic ที่วันนี้มีผู้ใช้แอปเดียว |
| 2026-09-11 | ค่าตั้งต้นของ fill ชี้ไป `info-default` ไม่ใช่ `brand` | วัดแล้วว่าแอปแรกที่ใช้แสดง `#06b5ed` ซึ่ง = `info-default` ที่นั่นพอดี ⇒ adopt แล้วสีไม่ขยับ · ถ้าเลือก `brand` แถบจะกลายเป็น `#0395d8` เห็นด้วยตา 5 จอ | แอปที่อยากให้แถบตามแบรนด์ต้อง override `--color-progress-fill` เอง |
| 2026-09-11 | `<div>` + ARIA ไม่ใช่ `<progress>` | UA stylesheet วาดคนละแบบทุกเบราว์เซอร์ และ Mediwork ถอด preflight ⇒ DS ห้ามพึ่ง reset ของแอป | เสีย semantics ของ element จริง ต้องประกาศ ARIA เอง (มีเทสคุม) |
| 2026-09-11 | ใส่ 4 โทนทั้งที่ใช้จริงแค่ 1 | แถบโควตาเปลี่ยนความหมายตามระดับเป็นเรื่องปกติ และจอ "เครดิตหมด" มีอยู่แล้ว ⇒ กัน fork ด้วย `className` ที่จุดแรกที่ต้องการ | 3 โทนที่ยังไม่มีใครใช้ — ถ้านานแล้วยังไม่มี ให้ถอดออก |
| 2026-09-11 | `size` มี `sm`/`md` ทั้งที่ของจริงมีแค่ 8px | เผื่อแถบในแถวตารางที่ 8px จะดันความสูงแถว | `sm` ยังไม่มีผู้ใช้ — เกณฑ์ถอดเดียวกับโทน |
