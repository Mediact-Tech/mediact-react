## สิ่งที่วัดไม่เจอ แต่ภาพกับเทสเจอ

รอบที่วัดครบ 19/19 แล้วยัง **ผิดอยู่สองจุด** — คนละแบบกับที่ตัวเลขจับได้:

- **ภาพจับ** — เคยซ่อนไอคอนทุกระดับ ทั้งที่ของจริงซ่อนเฉพาะเมนูย่อย
  (รางเส้นซ้ายทำหน้าที่บอกลำดับชั้นแทนอยู่แล้ว) เมนูระดับบน **มีไอคอนเสมอ**
- **เทสจับ** — ตอนยุบ ปุ่มเหลือแต่ไอคอน แล้วไม่มีชื่อให้โปรแกรมอ่านหน้าจอเลย
  `collapsedName()` จึงใส่ `title` + `aria-label` ให้เฉพาะตอนยุบ (Portal ใส่ `title` ไว้)

## พฤติกรรมที่ต้องรู้ก่อนใช้

### `expandOnHover` — ค่าเริ่มต้นเปิด

ยุบอยู่แล้วเอาเมาส์ไปวาง = กางออกชั่วคราว ตามพฤติกรรมจริงของ Portal
🔴 **รางกว้างขึ้นจริง 72 → 260** เนื้อหาข้าง ๆ ขยับตาม ไม่ใช่การลอยทับ
ถ้าไม่อยากให้เนื้อหาขยับให้ส่ง `expandOnHover={false}`

ทุกอย่างข้างในอ่าน `showExpanded` ไม่ใช่ `collapsed` ตรง ๆ — ไม่งั้นรางกว้างขึ้น
แต่ข้างในยังเป็นไอคอนล้วน

### `isChildActive` — จำเป็นเฉพาะตอนยุบ

ตอนรางยุบ เมนูลูกไม่ถูก render เลย ถ้าไม่บอกว่ากลุ่มไหนมีลูกเปิดอยู่
จะไม่มีอะไรบนจอบอกผู้ใช้ว่าอยู่หน้าไหน · `SidebarGroup` คำนวณเองไม่ได้เพราะเห็นแค่
`children` ที่ render มาแล้ว — ผู้เรียกเป็นคนรู้รายการเมนู

### `useSidebarState()` — ให้หัวราง/ท้ายรางรู้ว่ากางอยู่หรือยุบ

`header` กับ `footer` เป็น prop ก็จริง แต่ถูก **render อยู่ข้างใน** provider
(React ผูก context ตามตำแหน่งที่ render ไม่ใช่ตำแหน่งที่สร้าง element) ⇒ component
ที่ส่งเข้าไปเรียก hook นี้ได้เลย

จำเป็นเพราะ `expandOnHover` ทำให้ "กางอยู่หรือไม่" **ไม่เท่ากับ** `collapsed` ที่ส่งเข้ามา —
DS ถือ state ตัวนั้นไว้เอง ผู้เรียกจึงคำนวณเองไม่ได้ ของจริงที่ต้องใช้คือหัวรางที่สลับ
โลโก้เต็ม ↔ ตัวมาร์ค (wordmark กว้าง 3.8:1 ใส่ในคอลัมน์ 72px ไม่ลง)

### Escape ปิดได้เฉพาะโหมดลิ้นชัก

ตัวจับ Escape เช็ค `matchMedia("(min-width: 1024px)")` ก่อนเสมอ — โหมดลิ้นชักมีผล
ต่ำกว่า `lg` เท่านั้น (พื้นหลังทึบก็ `lg:hidden`)

🔴 ถ้าไม่กันไว้ แอปที่ผูก `mobileOpen` กับสวิตช์ยุบตัวเดียวกัน (ซึ่งเป็นวิธีที่ตรงกับ
พฤติกรรมเดิมของ hr-web ที่สุด) จะโดน Escape ที่กดปิด dialog **พับรางบนเดสก์ท็อป** ทิ้ง

### ข้อความเมนูตัดขึ้นบรรทัดใหม่ ไม่ตัดด้วย …

`wrap-break-word` ไม่มี `truncate` — เมนูภาษาไทยยาวกว่าอังกฤษเสมอ ถ้าตัดท้ายทิ้ง
ผู้ใช้จะแยกไม่ออกว่าเมนูไหนเป็นเมนูไหน (หัวกลุ่มยังใช้ `truncate` อยู่)

### ขนาดตัวอักษรบังคับเฉพาะเมนูย่อย

เมนูระดับบนสืบทอด 16px/lh-24 จากปุ่ม · ถ้าใส่ 14px ทุกระดับ เมนูบนจะสูง 41 แทน 46

## Props ที่ควรรู้

| prop | ค่าเริ่มต้น | ทำอะไร |
|---|---|---|
| `collapsed` | `false` | ยุบเหลือไอคอน |
| `expandOnHover` | `true` | ยุบอยู่แล้ว hover = กางชั่วคราว (รางกว้างขึ้นจริง) |
| `expandedWidth` / `collapsedWidth` | 260 / 72 | ความกว้างสองสถานะ |
| `supportAction` | — | ปุ่มติดต่อฝ่ายสนับสนุนก้นราง · `{ label, onClick, icon? }` ไม่ส่งก็ไม่มีปุ่ม |
| `footer` | — | บรรทัดท้าย (เวอร์ชัน) · ซ่อนอัตโนมัติตอนยุบ |
| `mobileOpen` / `onMobileOpenChange` | — | โหมดลิ้นชักต่ำกว่า `lg` — DS ไม่ได้จำสถานะให้ แอปคุมเอง |
| `linkComponent` | `"a"` | ใส่ `next/link` ได้ |
| `SidebarGroup.isChildActive` | — | ไฮไลต์หัวกลุ่มตอนราง**ยุบ** |
| `useSidebarState()` | — | hook อ่าน `{ isCollapsed }` จากข้างในราง (สำหรับ `header`/`footer`) |

ข้อความทุกตัวมาจากแอป — DS ไม่มี i18n

## โลโก้หัวราง — `brand` แทน `header`

`header` ให้แอปประกอบหัวรางเองทั้งก้อน ผลคือทุกแอปเขียนโค้ดชุดเดียวกันซ้ำ:

```tsx
<img src={isCollapsed ? "/icons/mark.svg" : "/icons/logo-full.svg"} className={isCollapsed ? "h-6" : "h-10"} />
```

⇒ ต้องมี **ไฟล์โลโก้ 2 ไฟล์ต่อแอป** และขนาดหลุดจากกันเงียบ ๆ — วัดจริง 2026-08-11:

| แอป | ไฟล์โลโก้เต็ม | สัดส่วน | ที่ `h-10` |
|---|---|---|---|
| MediHR | `medi-hr-logo.svg` 119×31 | 3.84:1 | 154×40 |
| Portal | `mediact-logo-full-white.svg` 1230×285 | **4.32:1** | **173×40** |

สูงเท่ากันแต่กว้างต่างกัน 12% โดยไม่มีใครตั้งใจ

`brand` แยกเป็น `symbol` (เห็นตลอด) · `name` (เห็นเฉพาะตอนกาง) · `action` (ปุ่มปิดลิ้นชัก)
DS ตัดสินเองว่าตอนยุบเหลืออะไร ⇒ แอปเหลือไฟล์เดียวคือเครื่องหมาย

```tsx
<Sidebar brand={{ symbol: <img src="/icons/mark.svg" className="h-6" />, name: "MEDI ACT" }} />
```

### 🔴 `name` เป็นตัวหนังสือได้ แต่ไม่ใช่ letterform ของแบรนด์

ตรวจไฟล์จริงทั้งสองแอปแล้ว: `medi-hr-logo.svg` และ `mediact-logo-full-white.svg`
**ไม่มี `<text>` และไม่มี `font-family` เลยสักตัว** — ตัวหนังสือถูกวาดเป็น `<path>`
(2 และ 15 path ตามลำดับ) ⇒ ส่งสตริงเข้า `name` จะได้ฟอนต์ของแอป ซึ่งเป็นคนละลายมือกับโลโก้

จึงรับ `ReactNode` ไม่ใช่ `string`: แอปที่ต้องคงลายมือแบรนด์ส่ง `<img>` เฉพาะส่วน wordmark
เข้ามา — ยังได้ประโยชน์เรื่องโครง (ไม่ต้องสลับไฟล์เอง · ตอนยุบ DS จัดการให้) โดยไม่แตะแบรนด์

`header` ยังใช้ได้และ**ชนะ**เมื่อส่งมาทั้งคู่ (ผู้เรียกเดิม 2 แอปยังไม่ต้องแก้)
